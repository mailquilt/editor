# Decisions

Accepted limits, and rules a review doesn't raise again unless something has changed since, such as a bug report or a new feature that depends on them. A PR that changes one of these says so, gives the reason and updates this page.

Which module owns what, and why, is in `docs/adr/`:

- The key map and the text's keys, ADR 0004, 0008 and 0014.
- Places, key scopes, positions and labels, ADR 0007, 0012 and 0015.
- Selection, focus and presses, and focus after an update, ADR 0011 and 0016.
- What `<mail-quilt>` holds, and the modules it makes, ADR 0009 and 0012.
- The panels' interface, ADR 0004 and 0016.
- Block types across the packages, ADR 0013.
- The canvas's styles, ADR 0006.
- The renderer's modules, and Columns' width, ADR 0005 and 0010.
- Rich text, ADR 0001 and 0003, and Merge Tags in it, ADR 0017.
- What a copy puts on the clipboard, ADR 0018.
- Where the Social Block's icons come from, ADR 0019.
- The editor's Modes and Selection bar, ADR 0021.
- Email style, and the order a Block's look comes from, ADR 0022.

## Keys and focus

- `keyboard.mdx` writes every key it names in `<kbd>`. It names every key the key map names, and none it doesn't, and a unit test checks both. (#164)
- Keys heard before any place, during a drag, while a tooltip shows or held down, are in the key map's `HEARD_FIRST`, asked with `keyHeardFirst` by the module listening then, so key dispatch has no action it can't run. (#178)
- A key acts only with the modifiers the key map gives it. Escape, Tab in a toolbar, and Enter on a Block or held down act with any. (#145)
- An action that does more from the keyboard, such as moving focus to a neighbour or showing a focus ring, takes `fromKeyboard`, which a button's click gives as `detail === 0`. That's the one way the editor asks. (#220)
- When an update removes or disables the element with focus, focus goes to the same thing again, or else to the nearest one left: a Selection bar control gives way to the one that took its place, or the bar's first, a Block's text to the Block, More's controls to More's button once it's closed, the link field and the format bar to the text, and Undo and Redo in the top bar to each other. With none left, the floating toolbar takes it, as it does when a new `value` takes away the text that had focus, or in Style and Check, where it isn't shown, the Mode's tab, or behind the narrow notice, the notice itself. Selecting what's already selected is no change. (#146, #214, #314, #315, #320)
- Escape closes one thing and stops there: the focused control's tooltip, the link field, what was typed in a settings field, a Shell menu, or the Selection bar's popover, chip menu or More, each of which goes back to its button. In a Block's text it goes back to the Block and stops, and in the Selection bar it goes back to the selected Block, or with a Row selected to that Row's first Block, as a selected Row's Blocks aren't stops for Tab. A hovered tooltip closes and the Escape goes on. An Escape that does none of these, such as in a bar field with nothing typed, reaches the host page, so a host's dialog can close. (#66, #78, #79, #315)
- A key that an input method handled does nothing, so an Escape that ends a composition doesn't close a tooltip either. The link field still keeps every key to itself. (#66, #78, #145)
- Ctrl/⌘+Z and Ctrl/⌘+K reach the host page unless the editor acts on them. Ctrl/⌘+K acts only with a Block that has text selected, and undo and redo only with a step to take. (#79, #165, #212)
- Typing in a Block's text or a settings field reaches the host page, as typing in any field does, seen as coming from `<mail-quilt>` or `<mail-quilt-shell>`. The link field keeps every key. `keyboard.mdx` says so, and how a host skips those keys. (#212)
- Alt+← and Alt+→ never go back a page from anywhere in the editor, the narrow notice and the email in Check too, and during a drag. On a Mac, in text, they still move by word. (#54, #79, #145, #165)
- Shift+Ctrl/⌘+B, I and U format text too, or the browser would format it outside the editor on Windows and Linux. (#78)
- The Modes are one Tab stop, a tab list chosen as focus reaches each Mode. With nothing in the email, Style and Check are off with `aria-disabled` rather than `disabled`, so the arrow keys still reach them and their tooltip says why. The Shell's Export is off the same way. Check has no Desktop/Phone switch, as it shows both widths, which the picked frames draw and the ticket's "every Mode" didn't. (#314)
- The email is one Tab stop: of its Blocks, only the selected one, or with nothing selected the first, and only the selected Block's text. With a Row selected, no Block is. So Tab from a Block or a Row reaches its settings, in the Selection bar ([ADR 0020](../adr/0020-make-the-email-one-tab-stop.md)).
- The Selection bar is one Tab stop, at its chip, or with nothing selected its first field, in the DOM after the email so Tab from the selected Block reaches it, and drawn above it. The arrow keys go along its controls, and in a field they move the cursor and go on from either end of its text, so a field doesn't trap them. Shift+Tab leaves from the stop, as from a toolbar. A Row whose Columns are all empty is selected by focus on one of its Columns' toolbars, as it has no Block to start from and its toolbar is gone. (#315)
- The bar is three places, `blockBar`, `rowBar` and `emailBar`, by what's selected, each with the keys the Block's toolbar, a Row's toolbar and the floating toolbar had, so the key map keeps one rule per place. A field in it is `barField`, whose own keys are the field's, so Delete never deletes a Row while it's typed in. (#315)
- An empty Column has one button, one Tab stop, which opens the picker in the Column with focus on its first Block, and Escape goes back to it. It's named with the words it shows and where it is, "Add a Block, or drop one here, in Row 1, Column 2", so its name holds what's on screen (WCAG 2.5.3) and a Row of empty Columns is one stop per Column. (#60, #78, #280, #316)
- `/` opens the Add panel from a Block, the Selection bar outside its fields, an empty Column's button and the floating toolbar, and is typed in text and fields. Shift+`/` does too, as the key map matches a key with exactly its modifiers, and on a layout such as German, `/` is Shift+7. (#316)
- The Add panel opens with focus in its search, and while it's docked it stays open as Blocks are added from it, so several can be added. Where it floats over the Canvas's start, it closes once it adds, as the new Block, and the text focus goes into, could be under it. Escape closes it, and focus goes to the selected Block, which may be one it added, or else back where it was. The picker closes with Escape, back where it was opened from, and with a press or focus anywhere else. In either search, Enter adds the first that's shown, ↓ goes to the tiles, and undo and redo are the editor's, as in a field in the Selection bar, so what was just added can be taken back. A press on a tile keeps focus where it is, so a drag that ends back on the panel leaves the text cursor. (#316)
- The Rows list's Rows are one Tab stop, `rowsItems`: the Row that's selected or holds the selected Block, or else the first, with the arrow keys, Home and End between them. Focus on a Row doesn't select it, so Tab through the list leaves the selection alone. Enter or a click selects it, scrolls the email to it and keeps focus on it in the list, so its keys go on working there. Alt+↑ and Alt+↓ move the Row with focus and select it, so the Selection bar shows what moved, and focus stays on it. Keyboard focus is a ring further out than the current Row's, so a focused Row and the current one are told apart. A Row's tooltip, with those keys, shows only for keyboard focus and after the Row, so hovering the pictures shows none and it never covers the Row before. The +'s layouts take focus on the first, and Escape, a press or focus elsewhere closes them, Escape back to the +. (#317)
- After Delete Block from the keyboard, focus goes to the neighbour and the deletion is announced. After Delete Row, the neighbouring Row is selected and focus stays in the Selection bar, so the next press deletes that Row, as it did when focus went to the next Row's toolbar. (#54, #315)
- Ctrl/⌘+D duplicates on a Block and in the Selection bar, so the Duplicate buttons' tooltips name a key that works where they are. Delete Row's names Delete too, and Delete Block's names none. Delete and Backspace delete only on a Block and in the bar with a Row selected, as #268 says: not in the bar with a Block selected, and never in text or a field. From the keyboard, focus goes to the copy, or for a Row stays in the bar, which shows the copy. (#276, #315)
- A Row whose Column widths aren't a layout's, which only an email made outside the editor has, is duplicated or pasted with even Columns, as many as it has, since `insertRow` takes its widths from a layout. (#276)
- Copy, cut and paste act on the browser's clipboard events, so its Edit menu works too, heard on the page and read from the element with focus, as Firefox fires them at the body and WebKit at `<mail-quilt>`. Ctrl/⌘+C, X and V keep their default to fire them. They act on a Block and in the Selection bar with a Row selected, a paste works in the bar with a Block or nothing selected too, and in the toolbar below the email. In text and fields they're the browser's own. More's Copy and Cut fire the browser's copy event with `execCommand("copy")`, the one way a page fires it with its own data in every browser without a permission, and Paste below reads the clipboard with `navigator.clipboard.read()`, which the browser asks the person to allow, and says why when it's refused. (#277, #315)
- A paste the editor refuses, such as a copy from a newer version, is announced with the reason and fires no `mq-error`, which is for the host's `value`. A pasted image file is used only when the clipboard has no text, as Word and Excel put a picture of the text beside it. (#277)
- The editor partly meets WCAG 2.2 AA. Below 640px, as at 400% zoom, it shows the narrow notice and the Selection bar can't be reached, which fails 1.4.10. The accessibility statement says so. (#143, #315)
- Check says "Loading preview…" in each frame only 150ms after the check starts, so a quick render shows and says nothing. A check that failed is tried again the next time Check opens, as the Preview did. A screen reader hears the result instead: the number of Problems, or that every check passed, from the editor's live region as the check ends, and again after each change made in Check, such as an undo. (#212, #320)
- A fix button in Check opens Edit, selects what the Problem is about and focuses its field, opening the Selection bar's popover or More that holds it. A Block's text is its field, and a list field, such as a Social Block's links, its first item. With no field, as for the unsubscribe link, it selects the last Row, where an email's footer is. The Problem shows under the field until focus leaves it or a press lands anywhere, and the live region says it after the field's name, so a screen reader hears why it's there. (#320)
- Check's tabs, Inbox, Plain text and HTML, are one Tab stop, a tab list chosen as focus reaches each, as the Modes are, with the key map's `checkViews`. The tab chosen stays while the editor is open, as Show sample values does. In Plain text and HTML, the text's box is the tab panel, a Tab stop after the Copy button so the arrow keys scroll it. Copy text and Copy HTML put the text on the clipboard through the browser's copy event, as More's Copy does, show "Copied" for 2 seconds, and say "Plain text copied." or "HTML copied.". Each copies as exported, with its Merge Tags, even while Show sample values shows samples in Plain text, so a sample never goes to every reader. A copy the browser doesn't make, with no copy event, is said: "Couldn't copy. Select the text and copy it instead." WebKit's `execCommand("copy")` returns false once the event is prevented, so a copy counts as done when the event came with somewhere to put the text. (#321)
- The floating toolbar stays, with Check in place of the Preview, as it holds focus after a press on the Workspace so keyboard undo and paste still work. Taking it away moves that focus to the Mode's tab, where the arrow keys change Mode. (#320)
- The narrow notice has no button until editing works on phones, as Check isn't drawn below 640px. It's a region named by its title that takes focus where nothing else in the editor can. (#320)
- In Style the email is `inert`: only to look at, so nothing in it takes focus, is typed in or is read out, as Edit has it to read and change. A press there lands on the workspace, which selects the Block under it, so the panel can say what that Block keeps as its own. A Block selected in Edit stays selected in Style, which is the keyboard's way to it. (#318)
- Style's settings are buttons named by the words they show, its name, then "Default" while it's unset, then its value, so the name holds what's on screen (WCAG 2.5.3). Each opens a popover with focus in the field it starts in, a color's Hex, a size's field or a font's search, its text selected to type over. Escape, a press outside or focus leaving it closes it, Escape back to its setting. The popover is drawn at the panel's end, so Tab from its last control, or Shift+Tab from its first, closes it and goes to the setting after its own, or back to its own, through the key map's `tabOutOfStylePopover`, rather than out of the panel. A font's search is a combobox, whose ↑, ↓ and Enter are the key map's `fontSearch`. A color's shade is a slider whose arrow keys, and with Shift ten times as far, are `colorArea`'s. Its keys at one time, a drag across it or along the hue, are one undo step, through `mergeKey`. (#318)
- The Link button is named "Edit link" when the cursor is on a link, and has no pressed state, as pressing it opens the link field rather than taking the link away. (#36, #67)

## The panels

- The panels' interface, `PanelApi`, isn't exported or documented yet. (#147)
- The selected Block's format bar and Merge Tag picker, and the picker between two Blocks, are fitted back inside the canvas by `tool-fitting.ts`, on a page that scales the editor too, and below the Selection bar, which sticks over the canvas's top. The format bar goes above the Block rather than be cut off. (#162, #315)
- The Selection bar shows each Block's two to four most-used settings, as the picked frames draw them, and More the rest, with no field shown twice: one list in `selection-bar.ts` says which keys the bar shows, and More shows every field of core's that isn't one of them. A setting of several fields, or a color, opens a popover from its button. (#315)
- More docks beside the email where the email, its gutters, More and the Rows list, or a docked Add panel in its place, fit side by side, and floats under the bar's end where they don't. Where the bar's controls don't fit with each field at its least, its Move, Duplicate and Delete go into More, and then its buttons with words show their icon alone. The bar measures this before it paints, and the element works out where More goes from its width, as a CSS container query can't see the docked More beside the Canvas. When a change scrolls a Block or Row into view, the bar comes into view first, so on a page that scrolls around a Shell it isn't left above the window. (#315)
- A Text Block's bar has its size, color and alignment, and the format bar stays at the text, as #315 says, rather than the formatting in the bar that frame `2-edit-text` draws. The email's bar has its preheader, language and width (frame `g03`). Its background and font are Page and Body in Style, so with nothing selected the bar has no More, and More closes when nothing is selected. (#315, #318)
- A Row's padding is one field while every side is the same, with "Same on every side" on, as frame `g09` draws it. The switch is under the popover's title, above the fields, so it stays where it was pressed as they change, and Tab reaches it before them, though the popover opens with focus in the first field. The switch isn't saved in the email: it's on wherever every side is the same, unless the person turned it off for that Row, or set one of its sides on its own, so the fields don't change under them once the sides happen to match. The bar keeps that while the editor is open. Turning it on gives every side Top's value, as one undo step, and the one field sets all four, as one too. (#315)
- The side panel is gone, as picked on 2026-11-26 (frame `a05`). The Add panel, opened by the email bar's Add or `/`, holds the Block types and the empty Rows' layouts, as frame `3-add-drag` draws it, and Saved Rows join it with #332. Where it docks, it takes the Rows list's place, and otherwise it opens over the list. It's 288px wide, four tiles across and narrower than More, so it docks before the email where the email, its gutters and the panel fit, from 968px for the usual email, and otherwise opens over the workspace's start, as More does at the other end. (#316)
- Style is the Canvas with the Email style panel at its end, as frames `5-style` and `s02`–`s04`, and `s10`–`s17`, picked on 2026-11-26, draw it, without the Rows list, the Selection bar, the Add panel or More. Width, preheader and language stay in Edit's email bar, so it has no Layout or Inbox section. The panel is 320px, More's width, and docks where the email, its gutters and the panel fit, 1000px for the usual email, and otherwise floats over the Canvas's end, as More does. A color's popover opens beside the panel, level with its setting, and moves up to fit; a size's and a font's open under theirs, or above where there's more room. Each scrolls in the room the editor and the window give it. Hovering or focusing a setting marks on the email what it changes, and what keeps its own value. Until #328, the font lists hold only system fonts, and the Selection bar's color fields keep the browser's picker. (#318)
- Check is the inbox at the email's width and at 375px beside "Before you export", as frames `6-check`, `c02`–`c05`, `c09`, `c10` and `m02` draw it. "Show sample values" is beside Check's tabs only while a Merge Tag has a `sample`. Where the Workspace is too narrow, both frames are drawn smaller, as one, side by side down to 80% and then the phone below, each scaled with `transform` in a slot of the size it's drawn at, as CSS `zoom` would need Firefox 126. So the desktop inbox still shows the desktop email rather than its phone layout, and the captions keep their size. It isn't a Tab stop, as a drag handle isn't, since `/` reaches the same Blocks, and a touch has no hover, so on a touch screen the Add panel and an empty Column's button add. Its picker has a search and says where it adds (frame `a02`). Lifted above its line at the Canvas's end, it stays below the Selection bar. An empty Column's picker has neither search nor footer, as frame `e05` draws it, where it's plain where it adds, and takes the place of the Column's button while it's open, so the Column grows to hold it. - An empty Column's button keeps `--mq-color-surface` behind it, where frame `e05` shows the email through it, as its words must be readable on any email's background, a dark one too. A tile dragged over a Column still tints the Column, as a dragged Block does. (#316)
- A Row dragged over a Column lands between Rows, on the drop line, as it did before, so frame `m05`'s refused drop doesn't happen and isn't built. (#316)
- Each module keeps its CSS beside its template, and styles shared by every surface are `theme.ts`'s. A custom property of the editor's own that isn't a theme token is named `--_mq-…`. Every shadow is a theme token's, apart from the white rings that keep a selection and the drop line visible on a dark email, and a color swatch's edge. (#220)
- The built-in dark theme, `theme="dark"` or `"auto"`, is `theme.ts`'s, with the colors of the picked 0.4.0 frames, except two. `--mq-color-danger` stays a red (`#ff7a6e`) where the frames draw orange, as the light theme's is red. `--mq-color-border-strong` is `#6f7179`, the frames' field edge, not their `#36373d` line, so a field's edge is at 3:1. It sets tokens on `:host`, so a host's token on the element still wins. (#330)
- Three things use a token differently in the dark theme, through `--_mq-…` values it sets: a color swatch's edge is light, so a dark color shows on a dark field; a Block's keyboard focus is `--mq-color-accent`, as `--mq-color-accent-strong` is pale there and the email under it is mostly white; and a switch's chosen segment is `--mq-color-surface-hover` on a `--mq-color-surface-muted` track, so it's lighter than its track, as in the frames and as the light theme's is. A host that sets every token for a dark theme itself keeps the light theme's use of them. (#330)
- The Shell passes `theme` to its editor, though the editor inherits the Shell's tokens, so what the editor draws from its theme rather than a token, the swatch's edge, follows it. (#330)

- Every word the editor and the Shell show or announce is in `strings.ts`, by ID, and a host replaces any through `strings`. A text that varies is one whole text with named placeholders, so it translates whole, such as one per move direction rather than a direction put into a sentence. A key's name is replaced where it's shown, by `keysInWords`, so the key map keeps its own names. `language` is a text too, for the `lang` of the editor's words and the lists it joins. (#312)
- Core's settings fields name their words by text ID, which the editor fills in, so a field's words are in one place with the rest. A unit test checks each ID core names is one of the editor's. Core's own messages, a refusal's reason among them, stay English, for developers: a paste refusal has a code the editor says in its own words, and a refused email's reason goes into the Shell's message as `{reason}`. (#312)

## Editing

- Links accept any `https:`, `http:`, `mailto:` or `tel:` URL, or a Merge Tag. (#36)
- A new Row from the Add panel, the Rows list's + or the email's "Start with a Row" is selected, as a dragged one is. (#54, #317)
- A new Block, added from the Add panel or the picker or dragged in, is selected and announced with its type and Position, such as "Text Block added, Row 3, Column 1, position 2 of 3." (#316)
- A drag scrolls a container only within 60px of its edge, and passes on to the next container once one can't go further. (#78)
- The email in Check has the host page's origin, with scripts still off, so the editor can refuse a file dropped on it and keep Alt+← from going back a page. (#165, #320)
- A file dropped on the editor is refused without `uploadImage`. With it, only the canvas takes files, and Check, the narrow notice and the top bar, the Shell's pieces in it too, still refuse them. Safari runs no listener in Check's email, so it still opens a file dropped there, in place of the page. Only a cover over the email during a drag could stop it, which image upload would replace. (#79, #161, #165, #212, #271)
- Import JSON has no confirm, and reads a file of any size. The person chose the file, and the JSON file is in the Export menu beside it. (#36, #205, #314)
- A pasted or dropped tab is a space, as the export shows it, where the canvas would show it at a tab stop no email client can draw. A tab already in a saved email stays until then. (#211)
- The editor and the Shell are left to right on any page, so the canvas matches the export until right-to-left emails are built. A heading the host gives the Shell takes its direction from its own text. (#166)
- `value` and each keystroke copy the whole email. That's fine at email sizes: a keystroke on an email of 600 Blocks takes 7 to 12ms to the next frame, of which the Shell's save is about 1ms, so the Shell saves each change at once. (#36, #219)

## The Shell

- With `save-key`, a saved email opens instead of the host's first `value`, and setting that first email again leaves the open email as it is. Removing `save-key` leaves the open email standing in, so a host that renders again can't replace the person's work. A different email opens, as on `<mail-quilt>`. An import stands in as a saved email does. (#42, #142, #160, #213)
- An email the host opens over a saved one is saved with the person's next change, while an import is saved at once. The Shell page says so. (#213)
- Reading `value` or calling `exportHtml()` before the first update starts the Shell, so `value` is the email the editor opens. (#79)
- `actions` isn't reflected back to its attribute. (#78)
- A saved email that can't be opened is kept under `<save-key>:unopened`, or `:unopened:2` and on, so no copy is lost. If it can't be copied there, nothing is saved over it, and the Shell says it can't save. (#66, #160, #213)
- Each kind of message in the Shell's message bar is kept apart, so none hides another. The Shell page says when each one goes. (#213)
- The Shell's name, save status, More and Export, and its messages, go in `<mail-quilt>`'s top bar through its `top-bar-start`, `top-bar-end` and `messages` slots. The slots are the Shell's, and not yet a promise to hosts, so the API page doesn't list them. `<mail-quilt>` with no email draws its top bar only when something is in them. The Shell's `header` part is the top bar, forwarded with `exportparts`. (#314)
- Export is one button with a menu of the Shell's exports. The save status shows only with `save-key`: "Saved" while the open email is the one saved under it, "Not saved" when the browser can't save, and nothing for an email the host opened that no change has saved yet. "Saving…" isn't shown, as the Shell saves each change at once. The ⋯ menu has Import JSON, and no "Keyboard shortcuts" item until there's a page of shortcuts in the editor to open. (#314)
- The Shell's messages and "Not saved" use `--mq-color-danger`, not a warning color of their own: a save that fails can lose the person's work, and a new token would be one more for a host's dark theme to set. (#314)

## Core and the document

- An insert or a removal gives its position as `at`, as a move gives `from` and `to`. An ID at the top of an Operation names what changed. (#80)
- `undo()` returns a boolean. (#36)
- A Command that would change nothing, such as `setRowLayout` to the layout a Row has, is refused with the code `unchanged`, and that's the only way it says so. (#52, #210)
- A color is checked as MJML's strict check takes it, which the export runs: at most one space after each comma, an alpha as `0.5` and not `.5`, and up to three digits in a channel, which CSS shows past 255 as 255. Loosening it would make emails that don't export, and tightening it would need a migration. (#210)
- A listener's error is thrown once every listener has heard of each change, from the call that started the changes. A Command a listener applies returns before anyone hears of it, so each listener hears of the changes in order. (#210)
- A saved language that isn't a code still loads, and can be sent back unchanged. Only a new one has to be a code, or one Merge Tag as its whole value. (#79, #274)
- A check on saved data that gets stricter comes with a migration, which raises the format version and rewrites what an older version saved as the check now takes it, so every email a release accepted keeps opening. A migration finds what it rewrites by the keys that hold it. (#209)
- A release that changes the format raises the version once, however many changes it holds. Its release notes say that emails it saves can't be opened by older packages, as a web app and a render worker on different versions would find. (#268)
- Version 3 is open on `main` until `0.3.0` is published: each pull request that changes the format extends the same version 3 schema and migration, and an email saved from `main` in between isn't supported. The version pull request is made only once all six features of the release are in, so nothing is published with half the format. (#268)
- The version 3 migration makes a Merge Tag a node only where it sits whole in one run of text, with that run's marks. A tag split across runs with different marks stays text: only an email written outside the editor has one, and the renderer still reads it across runs, so it exports the same. The editor makes one a node only when an edit touches it, with the marks of all its parts, as it does a tag whose `}}` is typed across them. (#272)
- Version 4 is open on `main` until `0.4.0` is published, as version 3 was. Email style is its first addition, one optional `style` object in the settings, so its migration from version 3 changes nothing but the version. Email style changes through its own Command, `updateEmailStyle`, which merges fields as the other Commands merge props, so `updateEmailSettings` keeps replacing a nested value whole. Once every field is cleared there's no `style` left, so the email is as it was before it had one. (#313)
- A link in a Text Block or Heading that sets its own color stays in that color, over Email style's link color, as the person chose it for that Block's background. Email style's body size sizes Buttons' labels too, as the built-in look gives Buttons and text the same size. (#313)
- An email is at most 1200px wide, and a font family needs at least one name. (#78)
- Exports from `core` marked "not a promise to hosts" are for Mail Quilt's own packages, and come from `@mailquilt/core/internal`, not the main entry. (#61, #84)

## Rendering

- MJML is given `fonts: {}`, so an exported email never loads web fonts. (#52)
- `mjml-browser` is pinned to one version, as the pass over its HTML reads its exact class and style text. A new one is taken on purpose. (#211, ADR 0010)
- `prosemirror-view` is held to 1.42 (`~1.42.9`). With 1.43.0, which handles mouse selection itself, a click back into a text put the cursor at its start in WebKit, and the install checks, which install with no lockfile, turned `main` red on it. Three editor browser tests fail on 1.43.0, so they say when a newer one can be taken. (#259)
- Dependabot keeps the lockfile current each week, a week after a release comes out, so the tests meet a new version of a package before a fresh install does. It was the install checks, which install with no lockfile, that found the `prosemirror-view` change, a day after it came out.
- Text and Headings get their line height in pixels, 1.5 times the font size rounded up, with `mso-line-height-rule:exactly`. With 1.5, classic Outlook drew thin lines under text. Core's styles give it, so the canvas shows the same height. (#95, #211)
- A word of 20 or more characters gets invisible break points after `/ . - ? & = _`, outside Merge Tags and a URL's `//`, which copy with it. The docs say so, and without them the email widens in five clients. A link's address never gets them. (#91, #205)
- A URL, a `www.` address or an email address written as text is exported as a link to itself, as the break points stop Apple Mail and Gmail linking it. A Merge Tag is never linked inside. (#91, #167)
- An address isn't linked when it runs straight into a character it can't hold, as in `a@b.c_d`, or right after an apostrophe. A URL or address that runs into a link isn't linked, so no link goes to part of one. (#167, #206)
- A URL or email address ends where letters of a language written without spaces start, such as Japanese, as that's the sentence far more often than the address. One with such letters typed in its path links only up to them. (#167, #211)
- A space other than HTML's own, such as a no-break space, goes to MJML as a character reference, because MJML trims every kind of space from the ends of a Button's label. A Merge Tag's spaces stay as typed, so it's still filled in. (#206)
- Any `&`, `<` or `>` in a Merge Tag is escaped, and a `"` too where the tag is in an attribute, such as a link or image URL. The docs say so. Tags should be plain names. (#53, #81)
- An Image in a Column narrower than its padding gets MJML's own negative width. Only very narrow emails reach it. (#36)
- A Row whose left and right padding add up to the email's width or more leaves its Columns no room: the canvas squeezes them to a letter a line, and the export gives them negative widths. Only an email 400px wide or narrower reaches it, and the canvas shows it as it's set. Core doesn't refuse it, as the email's width can change after the padding is set. (#279)

## Packages and the docs site

- CI's release job publishes on every commit on `main` that passes the checks, and `changeset publish` publishes only versions npm doesn't have, so the job needs no test for whether a commit is a release, and a failed publish goes out on a rerun. Each commit on `main` has a CI concurrency group of its own, so each release comes from the commit that versioned it. (#179)
- `PNPM_CONFIG_PROVENANCE` reaches `pnpm publish` in pnpm 11, so a publish that can't make provenance fails before it sends anything. (#227)
- The published packages are type-checked and built for ES2023, set in `@repo/typescript-config`. It's the lowest that runs core, the renderer and the editor: ES2023's array methods, and the renderer's lookbehinds, which need Safari 16.4. (#227)
- The editor has no `jsdelivr` or `unpkg` field. The CDN build is loaded by its full path, as `apps/docs/docs/html.mdx` shows. (#36)
- `@repo/typescript-config` stays in the published devDependencies, and core's types keep tsdown's bare `import "valibot"`. Neither affects installs. (#36)
- `withBase` stays: it's Blume's own helper. (#36)
- `loadDocument` runs before `renderEmail` on the docs pages, for a clearer build error. (#36)
- The docs site's `robots.txt`, which Blume writes, allows AI training. The docs are open and meant to be found. (#205)
- The React components take only the props that mean something on their element, as the API page lists. Two lines disable `react/immutability`, which reads an effect's `let` flag for a late result, React's own pattern, and setting the element's `value`, a DOM element in state, as changing state. (#224)
- The install checks read the published types with the repo's TypeScript and without `skipLibCheck`, and fail if a package of ours was installed from npm and not its tarball. (#224)
- The Vue, Angular and Svelte install checks use TypeScript 6, not the repo's 7: `vue-tsc`, Angular's compiler and `svelte-check` call TypeScript's JS API, which TypeScript 7 doesn't have, and Angular 22 asks for `>=6.0 <6.1`. They still read the published types without `skipLibCheck`. Vue and Svelte get the elements' types from `@mailquilt/editor/vue` and `@mailquilt/editor/svelte`, which a host references, as they import `vue` and `svelte`. The editor names both as optional peers of any version (`*`): without a peer, the types can't find `vue` under pnpm's global virtual store, and a narrower range makes npm refuse to install the editor beside Vue 2 or Svelte 4. Angular needs none: its templates read the element and event maps the editor already declares, and it never checks a property bound on an element. (#335)

## Tests

- The editor's modules that need no page have unit tests: the key map, positions and the Commands that move and drop, the text commands, field values, scaling and pasted HTML. The rest of the editor is tested in the browser, where a rule a unit test covers gets one case, to show the UI is wired to it. (#36, #145, #222)
- Browser tests find an element by role and name, or by a documented part. An element with neither, such as a drag handle, a Column or the Add panel, has a `data-testid`, and no selector uses a class. (#147) The rule is for the editor's own elements and the test pages. These are found otherwise: (#171)
  - The email's own markup, which has no roles or test ids: the text's paragraphs and marks and an Image's picture on the canvas, and the exported HTML, by its tags and MJML's classes.
  - A state, by the attribute that holds it, such as `aria-current`, `aria-pressed` or `data-drag-ghost`.
  - A control's icon, by its `svg`, and the host page's `html` and `body`, which hold what a test records.
  - Code run in the page, which has no locators, by tag and role attributes.
- In CI the editor's browser tests run on four workers, one for each of the runner's cores, where Playwright's default is half of them. WebKit keeps two and has four shards where the others have two: on four workers its jobs ran slower than on two, and a test timed out. The dark theme's accessibility test, with about a dozen scans, is marked slow, as it ran past its timeout on four workers in Firefox too. Locally they keep the default.
- A pull request that changes only files no check reads, such as `docs/`, the changesets and the agent docs at the root, is linted and has its changesets checked, and its build and tests are skipped. The skip is decided on the whole pull request against `main`, never on its last push, as a newer push cancels the run for the one before. `README.md` and `PROJECT.md` are checked in full, as the install checks read their CDN URLs. A push to `main` is always checked in full.
- The Node 22 tests run in a job of their own, beside the Node 24 ones.
- CI fails on a test that passes only on a retry, so a flake is seen and fixed. The retries stay, to tell a flake from a test that always fails. The trace kept is the first run's, the one that failed. (#171, #221)
- A test that reads an opacity the editor fades, such as a toolbar's on hover, runs with `reducedMotion: "reduce"`, which turns the fades off. WebKit in CI has stopped a fade partway until the page was next drawn, and the test read the half-faded value.
- Tests copy and paste through events, not the system's clipboard, which tests running at the same time could share. One test copies a Block and a Row between two pages through the system's clipboard in each browser, as ADR 0018 asks, since browsers clean pasted HTML differently. (#171, #277)
- A Command applies at once, and the test host's state has the change before a test can read it, so a test reads the editor's value, or the host's, once, right after an action. A poll would let a change that came late pass. Tests poll only for what settles later, such as layout, the Shell's saves and timers. (#221)
- Core keeps a "stores…" test for each Block type's own settings. (#82)
- The renderer's plain Node test builds the renderer into a folder of its own, so it never runs an older build of it, and never changes a `dist` that another task is reading. The install checks import the packed renderer by name. (#211)
- `focusStartOfTextBlock` is written in the editor's and the React package's browser tests and in the install checks. Sharing it would cost more than the copies. (#205)
