There's no Mail Quilt component for these frameworks. The editor is a Web Component, so each of them uses the `<mail-quilt>` element directly, as the [quick start](./quick-start) does. Mail Quilt's tests build the code on this page in a Vue 3.5, an Angular 22 and a Svelte 5 app, type-check it, and run it in a browser, so it works as written.

```package-install
npm install @mailquilt/editor
```

Four things change from framework to framework:

- **Telling the framework** that `<mail-quilt>` is an element, not one of its own components.
- **Passing the email as a property.** An attribute can only be a string, and `value` is an object.
- **Listening for `mq-change` and `mq-error`,** the editor's events.
- **Typing the element,** so its properties, its events and `exportHtml()` are checked.

Each example opens an email, saves every change in the browser, shows the reason if the editor refuses an email, and exports the email as HTML. In your app, save each email to your server from `mq-change` instead, as [Save emails to your server](./save-emails) shows. The [editor's API](./api#the-editor) lists everything the element has.

## Vue

Tell Vue's compiler that tags starting with `mail-quilt` are custom elements, in your Vite config:

<include meta='title="vite.config.js"'>
  ./_quick-start/vue/vite.config.js
</include>

Then use the element in a component:

<include meta='title="src/email-editor.vue"'>
  ./_quick-start/vue/src/email-editor.vue
</include>

- **`:value.prop`** sets `value` as a property. Vue already prefers a property when the element has one, and `.prop` makes sure.
- **`@mq-change` and `@mq-error`** listen for the editor's events. Vue adds them as it makes the element, so they hear even the first email being refused.
- **`shallowRef`** keeps the email as the plain object the editor sent. Each change sends a whole new email, so there's nothing inside it to watch.

For types, add this file to your `src` folder:

<include meta='title="src/mail-quilt.d.ts"'>
  ./_quick-start/vue/src/mail-quilt.d.ts
</include>

`@mailquilt/editor/vue` tells Vue's templates about `<mail-quilt>` and `<mail-quilt-shell>`: their properties as props, `$event` in `@mq-change` and `@mq-error`, and the element `useTemplateRef` gives you. Without it, `vue-tsc` doesn't check any of them.

[Vue and Web Components](https://vuejs.org/guide/extras/web-components.html) has the details.

## Angular

Add `CUSTOM_ELEMENTS_SCHEMA` to the component that uses the element, so Angular doesn't treat `<mail-quilt>` as an unknown element:

<include meta='title="src/app/email-editor.ts"'>
  ./_quick-start/angular/src/app/email-editor.ts
</include>

- **`[value]`** sets the element's `value` property, as Angular's property bindings do.
- **`(mq-change)` and `(mq-error)`** listen for the editor's events. Angular adds them as it makes the element, so they hear even the first email being refused.
- **`#editor`** is the element, which the Export button passes to `exportHtml`.

There's nothing to add for types. Unless your `tsconfig.json` turns `strictTemplates` off, Angular types `$event` in `(mq-change)` and `(mq-error)`, and `#editor`, from the types `@mailquilt/editor` gives the element. Angular doesn't check what's bound to an element's properties, so it doesn't check `[value]`.

Angular's [advanced component configuration](https://angular.dev/guide/components/advanced-configuration) covers `CUSTOM_ELEMENTS_SCHEMA`.

## Svelte

Svelte knows `<mail-quilt>` is a custom element from the dash in its name, so there's nothing to set up. Use the element in a component:

<include meta='title="src/email-editor.svelte"'>
  ./_quick-start/svelte/src/email-editor.svelte
</include>

- **`value={email}`** sets `value` as a property, because the element has one. Importing `@mailquilt/editor` defines the element before the component renders, so it's there when Svelte checks.
- **`onmq-change` and `onmq-error`** listen for the editor's events, as Svelte 5 names an event attribute: `on` and then the event's name. Svelte adds them as it makes the element, so they hear even the first email being refused.
- **`$state.raw`** keeps the email as the plain object the editor sent. Each change sends a whole new email, so there's nothing inside it to watch.

For types, add this file to your `src` folder:

<include meta='title="src/mail-quilt.d.ts"'>
  ./_quick-start/svelte/src/mail-quilt.d.ts
</include>

`@mailquilt/editor/svelte` tells Svelte about the attributes of `<mail-quilt>` and `<mail-quilt-shell>`: their properties, and the events `onmq-change` and `onmq-error` get. Without it, the events have no types, which strict TypeScript refuses, and the properties aren't checked.

## The Shell

`<mail-quilt-shell>`, a whole editor page with the email's name, Export and Import, and saving in the browser, is used the same way, and the types above cover it too. [The Shell](./shell) says what it takes.

## With server rendering

In Nuxt, Angular with server rendering or SvelteKit, the server sends an empty `<mail-quilt>`, and the editor starts in the browser. These setups haven't been tested. The [Next.js](./nextjs) page shows how it works in a setup that has been.
