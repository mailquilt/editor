`@mailquilt/core` is the part of Mail Quilt that knows what an email is. The editor is built on it: every drag, key press and setting in the editor becomes one of the Commands on this page. Your code can send the same Commands, in a browser or in Node.

```package-install
npm install @mailquilt/core
```

## Build an email

`createEmail()` makes a new email. `createEditor()` wraps an email so you can change it with Commands and undo what you did. What it returns has no screen: it's the email and its history, which is what `<mail-quilt>` keeps inside it.

<include meta='title="build-an-email.js"'>./_code/build-an-email.js</include>

The last Command sets a color that isn't one, so it's refused. `refused.ok` is `false`, `refused.code` is `"invalidProps"`, and `refused.reason` reads:

```text
Invalid props for Block "8f5b928cfc0fd74ae8": color: Must be a color written as #rgb, #rrggbb, rgb(255, 0, 0) or rgba(255, 0, 0, 0.5), with at most one space after each comma
```

`getDocument()` returns the email as it stands. Save it, pass it to `<mail-quilt>` as `value`, or [render it](./render-on-a-server).

## Commands

A Command is a plain object with a `type`. `apply()` returns `{ ok: true }` when the email changed, with a `createdId` for what it added: the new Block's ID from `insertBlock` and `insertBlockInNewRow`, and the new Row's from `insertRow`. Otherwise it returns `{ ok: false, code, reason }` and the email is unchanged. `reason` says why in English, for a person to read. `code` says what kind of refusal it is, for your code to match on, and is one of these:

| `code` | The Command was refused because |
| --- | --- |
| `invalidCommand` | it isn't a Command, or one of its fields isn't what that Command takes, such as a negative index or an unknown layout. |
| `invalidProps` | its `props` or `settings` would give the Block, Row or email a value it can't have, such as a color that isn't one. |
| `noSuchBlock`, `noSuchColumn`, `noSuchRow` | the email has no Block, Column or Row with the ID it names. |
| `unknownBlockType` | its `blockType` isn't one of the Block types. |
| `indexPastEnd` | its index is past the end of the Column, or of the email's Rows. |
| `unchanged` | the email is already as it asks, so nothing went wrong. |

| `type` | Other fields | What it does |
| --- | --- | --- |
| `insertBlock` | `blockType`, `columnId`, `index` | Adds a Block to a Column. |
| `insertBlockInNewRow` | `blockType`, `rowIndex` | Adds a Row with one Column, holding a new Block. |
| `updateBlockProps` | `blockId`, `props` | Changes a Block's content or settings. |
| `moveBlock` | `blockId`, `columnId`, `index` | Moves a Block within its Column or to another. |
| `moveBlockToNewRow` | `blockId`, `rowIndex` | Moves a Block into a new Row of its own. |
| `removeBlock` | `blockId` | Removes a Block. |
| `insertRow` | `index`, `layout` | Adds an empty Row with a layout, such as `"50/50"`. |
| `setRowLayout` | `rowId`, `layout` | Changes a Row's layout. |
| `updateRowProps` | `rowId`, `props` | Changes a Row's settings. |
| `moveRow` | `rowId`, `index` | Moves a Row, with its Blocks. |
| `removeRow` | `rowId` | Removes a Row. |
| `updateEmailSettings` | `settings` | Changes the email's width, background, font, preheader or language. |

A Block's type is one of `text`, `heading`, `image`, `button`, `divider` and `spacer`. A layout is one of `100`, `50/50`, `33/67`, `67/33`, `33/33/33` and `25/25/25/25`, written as a string. Both lists are exported. `ROW_LAYOUTS` is the layouts as strings, and `BLOCK_TYPES` is an array of `{ type, label }` objects. In TypeScript, a type is a `BlockType`.

`props` and `settings` hold only what you're changing. The rest stays as it is. To remove an optional property, set it to `null`:

```js
editor.apply({
  settings: { preheader: null, width: 640 },
  type: "updateEmailSettings",
});
```

The [document format](./document-format) page lists each Block's properties and what they accept.

## Undo and redo

Each Command that's accepted is one step. `undo()` and `redo()` return `false` when there's nothing to undo or redo. `canUndo()` and `canRedo()` tell you beforehand, so you can disable your own Undo and Redo buttons, as the editor does.

```js
editor.undo();
editor.redo();
undoButton.disabled = !editor.canUndo();
```

To make several Commands one step, give them the same `mergeKey`. The editor does this while someone types, so that a word is undone at once rather than a letter at a time. If property changes end where they started, as when someone types a letter and deletes it, they leave no step to undo, even when changes to several Blocks take turns.

```js
editor.apply(first, { mergeKey: "import" });
editor.apply(second, { mergeKey: "import" });
```

## Listening for changes

`subscribe()` calls you after every change, including undo and redo, with what changed. It returns a function that stops the calls. Subscribing a function that's already subscribed adds nothing, and either function you got back stops it.

```js
const stop = editor.subscribe((operations) => {
  save(editor.getDocument());
});
```

A listener that throws doesn't stop the others hearing of the change. Once they all have, its error is thrown from the `apply()`, `undo()` or `redo()` that made the change, which still happened. A listener can apply a Command of its own. Its `apply()` returns before anyone hears of it, as each listener hears of every change in order, so an error from hearing of it is thrown from the call that made the first change.

Each Operation is a record of one thing that happened to the email, and is plain JSON. One Command can produce several. An ID at the top of an Operation always names what changed, such as `blockId` in a move. These are all of them:

| `type` | What it says |
| --- | --- |
| `insert` | A Block, Column or Row was added: `block`, `column` or `row`, with the whole of what was added, and `at`, where it is now. |
| `remove` | A Block, Column or Row was taken out: `block`, `column` or `row`, with the whole of what was removed, and `at`, where it was. |
| `move` | A Block moved, with `blockId`, or a Row did, with `rowId`. `from` is where it was, and `to` where it is, as an index once it had left `from`. |
| `setProps` | A Block's, a Row's or the email's settings changed, named by `blockId`, `rowId` or `emailSettings: true`. `props` holds all of them after the change, and `previousProps` all of them before it. |
| `setColumnWidth` | A Column's width changed: `columnId`, its `width`, and its `previousWidth`, as percentages. |

A Block's position, in `at`, `from` or `to`, is `{ columnId, index }`. A Column's is `{ rowId, index }`, and a Row's is `{ index }`:

```js
const operations = [
  { type: "insert", at: { columnId: "c1", index: 0 }, block: newBlock },
  {
    type: "move",
    blockId: "b1",
    from: { columnId: "c1", index: 0 },
    to: { columnId: "c2", index: 1 },
  },
  { type: "move", rowId: "r2", from: { index: 1 }, to: { index: 0 } },
  { type: "remove", at: { rowId: "r1", index: 1 }, column: oldColumn },
  {
    type: "setProps",
    blockId: "b3",
    props: { label: "Shop now" },
    previousProps: { label: "Buy" },
  },
  { type: "setColumnWidth", columnId: "c2", width: 40, previousWidth: 50 },
];
```

## Checking an email

`loadDocument()` checks a value that's meant to be an email, such as one that arrived in a request. It returns the email, brought up to the current version of the format if it was saved by an older one, or the reason it was refused.

```js
import { loadDocument } from "@mailquilt/core";

const loaded = loadDocument(JSON.parse(body));
if (!loaded.ok) {
  return new Response(loaded.reason, { status: 400 });
}
await saveEmail(loaded.document);
```

`createEditor()` runs the same check and throws if the email fails it.

`isSameDocument(first, second)` tells you whether two emails are the same, whatever order their keys are in. The editor uses it to tell an email you pass back from one that's new.

## Before you rely on it

Mail Quilt is at version `0.x`, so Commands may gain fields or change names between releases. Saved emails are different: each has a `version`, and a newer Mail Quilt brings an older email up to date when it loads it.
