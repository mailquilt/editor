The editor is the `<mail-quilt>` element, and the [Shell](./shell) is `<mail-quilt-shell>`, the editor with the email's name, Export, Import and messages added. `@mailquilt/editor` registers both, and `@mailquilt/react` wraps both as components.

## The editor

`<mail-quilt>` has eleven properties, two events and two methods:

| Name | What it does |
| --- | --- |
| `value` | The email the editor shows. Set it to open an email, or to `undefined` or `null` to empty the editor. |
| `uploadImage` | A function that uploads an image to your storage and returns a promise of `{ url }`. With it, the Image settings have an Upload image button, and image files can be dropped or pasted on the email. [Upload images](./upload-images) shows one, and what the editor does with it. |
| `mergeTags` | Your app's Merge Tags, as an array of `{ name, label, sample, unsubscribe }`, such as `[{ name: "first_name", label: "First name", sample: "Ana" }]`. `name` is what goes between the braces, and the rest are optional. With it, typing `{{` in text, or in any setting that holds text or a URL, opens a list of them to pick from, and the format bar has a Merge Tag button. A tag in text shows its label, or its name without one, but the export always has `{{name}}`. `sample` is what Check shows in the tag's place with Show sample values on, and `unsubscribe: true` marks your unsubscribe link's tag, which Check then looks for. [Merge Tags](#merge-tags) says more. |
| `fonts` | Your app's web fonts, as an array of `{ name, url, fallback }`, such as `[{ name: "Inter", url: "https://fonts.googleapis.com/css2?family=Inter&display=swap", fallback: "Arial, Helvetica, sans-serif" }]`. Style's font lists offer them as Your fonts, above the system fonts. Without it, the lists hold only system fonts. [Web fonts](#web-fonts) says more. |
| `starterEmails` | Your app's Starter emails, as an array of `{ name, description, email }`, such as `[{ name: "Product launch", description: "Hero, two products, quote", email: launchEmail }]`. While the email has no Rows, a start screen offers them as cards, after Blank, and picking one makes the email a copy of it. Without it, there's no start screen. [Starter emails](#starter-emails) says more. |
| `sender` | Who the email is from, such as your customer's business name, which Check's inbox shows above the subject. Without it, the inbox shows no sender. |
| `sendTest` | A function that sends a test of the email through your own sending service, to whoever you choose, such as the person signed in, and returns a promise. It gets `{ html, text, subject }`: the email as `exportHtml()` and `exportText()` give it, with its Merge Tags as written for your service to fill, and your `subject`. With it, Check has a Send a test button, which is off until the email is checked and while a test sends. When the promise resolves, Check says "Test sent." When it rejects with an `Error`, Check shows its message, so write it for the person, such as how many tests their plan has left, or "The test wasn't sent. Try again." when it has none. |
| `socialIconsUrl` | The URL of a folder in your storage holding the Social Block's icons, copied from `@mailquilt/renderer`'s `icons`. The canvas, Check and `exportHtml()` load the icons from there. Without it, they load from jsDelivr, at the renderer's exact version. [Social icons](./social-icons) says why you might set it. |
| `strings` | Your own words for any of the editor's, by ID, such as `{ "topBar.undo": "Annuler" }`. Any you leave out stay in English. [Text in your words](#text-in-your-words) says how to find the IDs. |
| `subject` | The email's subject, which Check's inbox shows before the preheader. Without it, the inbox shows the preheader alone, or the email's first words when it has no preheader. |
| `theme` | The editor's built-in theme: `light`, the default, `dark`, or `auto`, which follows the person's system. An attribute too, such as `theme="dark"`. A [theme token](./theme-tokens) you set wins over either theme, and the email keeps its own colors. [A dark theme](./theme-the-editor#a-dark-theme) says more. |
| `mq-change` | An event fired after every change. The new email is in `event.detail.document`. |
| `mq-error` | An event fired when the editor refuses an email, which then keeps the email it had. The reason is in `event.detail.reason`. The [document format](./document-format) page lists what the editor accepts. |
| `exportHtml()` | Returns a promise of the email's HTML, ready to send. It rejects if the editor has no email. |
| `exportText()` | Returns the email as plain text, to send beside its HTML for email apps that show only text, as `renderText()` writes it on a [server](./render-on-a-server#plain-text). It throws if the editor has no email. |

Some of those checks are stricter than CSS. A color is checked as MJML checks it, so every email the editor opens can also be exported: at most one space after each comma, an alpha written as `0.5` and not `.5`, and no named colors such as `red`. A font list goes into the email's CSS, so it holds only font names: letters A to Z, digits, spaces, hyphens, underscores, commas and quotes that close. The [document format](./document-format#colors) page has every rule.

Opening a different email clears undo history. Setting `value` to the email the editor last sent you changes nothing, even if you copied it or its keys come back in another order. That's why you can save each change and pass it straight back.

[Two things to get right](./quick-start#two-things-to-get-right) says which email to pass back, and when to start listening for `mq-error`.

### Merge Tags

Give the editor your app's Merge Tags, and people pick one as they type, instead of remembering its name:

```js
editor.mergeTags = [
  { name: "first_name", label: "First name" },
  { name: "company" },
];
```

- Typing `{{` in a Text or Heading Block opens a list of the tags at the cursor. What's typed after `{{` narrows it, by name and by label, whatever the case.
- With an input method, as for Japanese, the list narrows by the characters in the text, so a label in kanji matches once the typed kana are converted to it. While a word is being composed, its keys go to the input method. Once it's committed, <kbd>Enter</kbd> puts in the highlighted tag. Japanese input types `{` as `『`, so people type the braces with English input, or use the Merge Tag button.
- <kbd>Up</kbd> and <kbd>Down</kbd> move through the list, <kbd>Enter</kbd> or
  <kbd>Tab</kbd> puts in the highlighted tag in place of what was typed, and
  <kbd>Escape</kbd> closes the list and leaves the text. A click on a tag puts
  it in too. Focus stays in the text throughout, which tells a screen reader the
  highlighted tag.
- The format bar's Merge Tag button types `{{` at the cursor, which opens the same list.
- Every setting that holds text or a URL opens the same list on `{{`: a Button's label and link, an Image's URL, alt text and link, the email's preheader and language, and the link field in text. There a tag goes in as the text `{{name}}`, which edits like any other text. <kbd>Enter</kbd> puts in the tag without applying the field, and the first <kbd>Escape</kbd> closes the list. The next one takes back what was typed, or closes the link field. With `mergeTags`, each of these fields says under it that `{{` adds a Merge Tag.
- A URL can start with a Merge Tag, but no scheme can follow it, so a tag can't wrap a whole URL, as in `{{#if vip}}https://example.com{{/if}}`. [Merge Tags](./document-format#merge-tags) has the rule.
- A tag typed by hand still becomes one unit when its `}}` is typed, whether it's in your list or not.
- A tag whose name is empty or has a brace in it isn't offered, as text can't hold it. Give the name without its braces.
- A tag's `sample`, such as `"Ana"` for `first_name`, is what Check shows in its place, in the email and in the inbox's sender, subject and preheader, while Show sample values is on. The switch shows only when a tag has a `sample`. The export always keeps `{{first_name}}`.
- Mark the tag that's your unsubscribe link with `unsubscribe: true`, such as `{ name: "unsubscribe_url", unsubscribe: true }`. Check then says so when no link in the email goes to it. With `mergeTags`, Check also says when a tag in the email isn't in your list.
- Setting `mergeTags` again only redraws the labels. The email doesn't change, so it fires no `mq-change`.

Without `mergeTags`, or with no tag it can offer, typing `{{` opens nothing and there's no Merge Tag button.

### Web fonts

Give the editor the web fonts your app allows, such as your customers' brand fonts, and Style's Headings and Body lists offer them as Your fonts, above the system fonts:

```js
editor.fonts = [
  {
    name: "Fraunces",
    url: "https://fonts.googleapis.com/css2?family=Fraunces:wght@400;700&display=swap",
    fallback: "Georgia, 'Times New Roman', serif",
  },
];
```

- `name` is the font's family name, as its stylesheet declares it. It's one name of letters, digits, spaces and hyphens, such as `DM Serif Display`.
- `url` is a stylesheet that declares the font, such as one from Google Fonts or your own storage, and must start with `https:`. It can't hold quotes, brackets, spaces or backslashes, which would end it in the exported HTML, so percent-encode any it needs.
- `fallback` is the fonts a reader sees where the web font doesn't load, such as `Georgia, serif`. Pick ones close to the web font in shape and width. Each web font in the list says "Falls back to" the first of them.
- People pick only from your list. They can't add a font of their own.
- A font picked is stored in the email with its name and URL, in `settings.fonts`, and the email's font is its name followed by its fallback, as in `'Fraunces', Georgia, 'Times New Roman', serif`. So the email exports and renders the same anywhere, even after you take the font off your list. An email whose font isn't on your list, such as one imported, still lists it under Your fonts while it's picked, but the editor doesn't load it into your page, as its stylesheet would apply to the whole page, so the editor shows its fallback.
- The export loads only the fonts the email uses: a font stops being stored once neither the Body nor the Headings use it, and a heading font in an email with no Heading isn't loaded.
- The editor loads each font from its URL into your page, so the email and the lists show it. While it loads, its setting says "Loading Fraunces…". If its stylesheet can't be loaded, such as when its URL is wrong or your [Content Security Policy](#content-security-policy) blocks it, the setting says so, and the email shows the fallback. Safari doesn't say when a font file named by a stylesheet that loaded is missing, so there the email shows the fallback without a message.
- A font whose name, URL or fallback the editor can't take, or whose name an earlier one has, isn't offered, and the editor says why on the console.

Many email clients, Gmail and Outlook among them, don't load web fonts and show the fallback instead. [Tested email clients](./email-clients#web-fonts) lists which do.

### Starter emails

Give the editor the emails your customers can begin from, and it offers them on a start screen while the email is empty:

```js
editor.starterEmails = [
  {
    name: "Product launch",
    description: "Hero, two products, quote",
    email: launchEmail,
  },
  {
    name: "Letter",
    description: "Heading, text, sign-off",
    email: letterEmail,
  },
];
// An email with no Rows, so the start screen shows.
editor.value = { ...createEmail(), rows: [] };
```

- The start screen shows only while the email has no Rows and the person hasn't started it. `createEmail()` from `@mailquilt/core` gives an email with one Row, so pass it with `rows: []`, as above. Once the email has had a Row, or the person picks Blank, it doesn't show again until you set a new `value`, even if they delete every Row or undo the pick.
- Each card shows the email's top, drawn as the Canvas draws it, then `name`, and `description` under it if you give one. Blank comes first, for an empty email.
- `email` is an email as `value` takes one, such as the JSON a Shell's Export JSON button gives you. It's checked as `value` is, and an email from an older version is brought up to date.
- Picking one makes the email a copy of it, settings and Rows, with new IDs, in one undo step, so Undo takes the email back to empty. The editor fires one `mq-change`, and a screen reader hears "Started from Product launch." A Row whose Column widths aren't one of the [layouts](./document-format)' gets even Columns, as a pasted Row does, which only an email written outside the editor has.
- A Starter email the editor can't open, or with no `name`, isn't offered, and the editor says why on the console.
- A new array at each render, as React gives, redraws nothing unless something in it changed.

[Give customers somewhere to start](./let-customers-design-emails#give-customers-somewhere-to-start) says how to make them.

### Text in your words

Every word the editor shows, or reads out to a screen reader, has an ID, and `strings` replaces any of them, such as to translate the editor. `STRINGS` lists every ID with its English, which is what shows for any you leave out:

```js
import { STRINGS } from "@mailquilt/editor/strings";

editor.strings = {
  language: "fr",
  "topBar.undo": "Annuler",
  "said.blockMoved":
    "Déplacé : ligne {row}, colonne {column}, place {position} sur {count}.",
};
```

- A word in braces, such as `{row}`, is filled in by the editor. Your text can put it anywhere, or leave it out. A Merge Tag in an example, such as `{{cta_url}}`, has two braces and is never filled in.
- `language` is the language your texts are in, `en` until you set it. The editor marks its own words with it, so a screen reader reads them in that language, and joins lists in it, such as the names of files it can't upload.
- Key names in tooltips and in what a screen reader is told to press have IDs too, such as `key.ctrl`, which a German keyboard calls `Strg`.
- A message about a refused email, such as the Shell's `shell.cantOpen`, fills `{reason}` with the reason in English, which is for developers. Leave `{reason}` out to show only your words. `mq-error` always gives the English reason.
- `@mailquilt/editor/strings` defines no elements, so a server can import it too.
- Setting `strings` again redraws the editor's words. The email doesn't change, so it fires no `mq-change`.
- Only English ships, and the email's own content is never changed.

## The Shell

`<mail-quilt-shell>` has the editor's properties, events and method, and three attributes of its own:

| Name | What it does |
| --- | --- |
| `value` | The email the Shell shows, as on `<mail-quilt>`. With `save-key`, a saved email opens instead of the first one you set. With no `value` and nothing saved, the editor is empty and Export is off. |
| `uploadImage` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `fonts` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `mergeTags` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `starterEmails` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `sender` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `sendTest` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `socialIconsUrl` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `strings` | As on `<mail-quilt>`. The Shell passes it to the editor inside, and its own words have IDs starting `shell.`. |
| `subject` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `theme` | As on `<mail-quilt>`, for the Shell's own header and messages too. The Shell passes it to the editor inside. |
| `heading` | The email's name, at the left of the top bar. It's "Email" when unset, or your `shell.email`. |
| `actions` | What the Shell offers, by name and separated by spaces: `export-html` and `export-json` in the Export menu, and `import-json` in the More menu. Leave it out to offer all three. |
| `save-key` | Where the email is kept in the browser, as the `saveKey` property. Use one for each email and each person. Leave it out to store nothing. [Saving](./shell#saving) says how it works. |
| `mq-change` | Fired after every change, including an import. The new email is in `event.detail.document`. |
| `mq-error` | Fired when the editor refuses an email you set as `value`. The reason is in `event.detail.reason`, and the message bar shows it too. |
| `exportHtml()` | Returns a promise of the email's HTML, as on `<mail-quilt>`. |
| `exportText()` | Returns the email as plain text, as on `<mail-quilt>`. |

## React

`@mailquilt/react` has two components, which render the same elements:

| Component | Props |
| --- | --- |
| `MailQuilt` | `value`, `onChange`, `onError`, `uploadImage`, `fonts`, `mergeTags`, `starterEmails`, `sender`, `sendTest`, `socialIconsUrl`, `strings`, `subject`, `theme` and `ref`. |
| `MailQuiltShell` | The same, and `heading`, `actions` and `saveKey`. `actions` is an array of names, such as `["export-html"]`. |

- `value` is the email to open. `onChange` gets the new email after every change, and `onError` gets the reason when the editor refuses one, or when the editor's code can't load. `onError` is always listening in time.
- `uploadImage`, `fonts`, `mergeTags`, `starterEmails`, `sender`, `sendTest`, `socialIconsUrl`, `strings` and `subject` are the editor's properties, which the component sets on the element once the editor has loaded. A new `fonts`, `mergeTags` or `starterEmails` array or `strings` object at each render redraws nothing unless something in it changed.
- `theme` is the element's attribute, so it's in the server's HTML too.
- `ref` gives you the element once the editor has loaded, so you can call `exportHtml()`.
- Other props go to the element: `aria-*` attributes, React's events such as `onKeyDown`, and `className`, `hidden`, `id`, `inert`, `lang`, `role`, `slot`, `style`, `suppressHydrationWarning` and `title`.
- On the server, each component renders its empty element, and the editor loads in the browser.

`@mailquilt/react` works with React 18 and 19. The [React](./react) and [Next.js](./nextjs) pages show both components in use.

## CSS parts

The frame around the editor, with its corners and its 1px ring, is the `frame` part. Style it with `mail-quilt::part(frame)`, such as `border-radius: 0` for an editor that fills a panel edge to edge. The top bar inside it, with Undo, Redo, the Modes and the Desktop and Phone views, is the `top-bar` part, and takes the frame's top corners. When the editor is narrower than {{editor-phone-width}} pixels, it's laid out for a phone inside the same frame, so what you give the frame, such as a height or corners, applies there too. Its sheets open from the bottom of the window, over your page, as modal dialogs do. In the Shell, the frame is the Shell's own, the `frame` part of `<mail-quilt-shell>`, and the editor inside draws none. Style it with `mail-quilt-shell::part(frame)`, and the top bar with `mail-quilt-shell::part(header)`. The Shell's own pieces of the top bar and its message bar are parts too, which [Customizing it](./shell#customizing-it) lists.

Colors, spacing, corners and the font are [theme tokens](./theme-tokens), not parts.

## Content Security Policy

The editor works under a policy that blocks inline styles, such as `style-src 'self'`. Only Check needs `'unsafe-inline'` in `style-src`:

```text
Content-Security-Policy: style-src 'self' 'unsafe-inline'
```

Check shows the email in sandboxed iframes, at desktop and phone width, which follow your page's policy, and emails rely on inline styles. Without it, Check shows the email without its styling, and still lists its Problems. The canvas and `exportHtml()` aren't affected, and the exported HTML is unchanged.

The canvas and Check show each Image Block from its URL, so if your policy has `img-src`, or a `default-src` without one, it has to allow the sites your emails' images are on. To allow any image over HTTPS:

```text
Content-Security-Policy: img-src 'self' https:
```

An image it blocks doesn't show on the canvas or in Check, and the exported HTML is unchanged. A Social Block's icons load from `https://cdn.jsdelivr.net`, so allow it too, or set [`socialIconsUrl`](./social-icons) and allow your own storage. The editor's own icons and arrows are part of the page, so it needs no other image source, such as `data:`.

With [`fonts`](#web-fonts), the editor adds each font's stylesheet to your page, which loads the font files it names. So `style-src` has to allow the stylesheets' site, and `font-src` the fonts' site. For Google Fonts:

```text
Content-Security-Policy: style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com
```

A font it blocks is said under its setting in Style, and the email shows the fallback. The exported HTML is unchanged.

With [`uploadImage`](./upload-images), the editor makes no request of its own. Whatever your function fetches, such as your storage's upload URL, has to be allowed by `connect-src`, and the URL it returns by `img-src`.

A page using the [CDN build](./html) also needs `script-src` to allow the folder the build is in, because the build is several files. The path must end in `/`:

```text
Content-Security-Policy: script-src 'self' https://cdn.jsdelivr.net/npm/@mailquilt/editor@0.3.0/dist/cdn/
```

If it allows only `dist/cdn/index.js`, the editor doesn't load. An inline script like the one in the [HTML example](./html) also needs a nonce or hash, or you can move it into a file of your own.
