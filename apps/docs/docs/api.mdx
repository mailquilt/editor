The editor is the `<mail-quilt>` element, and the [Shell](./shell) is `<mail-quilt-shell>`, the editor with a header and messages around it. `@mailquilt/editor` registers both, and `@mailquilt/react` wraps both as components.

## The editor

`<mail-quilt>` has two properties, two events and one method:

| Name | What it does |
| --- | --- |
| `value` | The email the editor shows. Set it to open an email, or to `undefined` or `null` to empty the editor. |
| `uploadImage` | A function that uploads an image to your storage and returns a promise of `{ url }`. With it, the Image settings have an Upload image button, and image files can be dropped on the email. [Upload images](./upload-images) shows one, and what the editor does with it. |
| `mq-change` | An event fired after every change. The new email is in `event.detail.document`. |
| `mq-error` | An event fired when the editor refuses an email, which then keeps the email it had. The reason is in `event.detail.reason`. The [document format](./document-format) page lists what the editor accepts. |
| `exportHtml()` | Returns a promise of the email's HTML, ready to send. It rejects if the editor has no email. |

Some of those checks are stricter than CSS. A color is checked as MJML checks it, so every email the editor opens can also be exported: at most one space after each comma, an alpha written as `0.5` and not `.5`, and no named colors such as `red`. A font list goes into the email's CSS, so it holds only font names: letters A to Z, digits, spaces, hyphens, underscores, commas and quotes that close. The [document format](./document-format#colors) page has every rule.

Opening a different email clears undo history. Setting `value` to the email the editor last sent you changes nothing, even if you copied it or its keys come back in another order. That's why you can save each change and pass it straight back.

[Two things to get right](./quick-start#two-things-to-get-right) says which email to pass back, and when to start listening for `mq-error`.

## The Shell

`<mail-quilt-shell>` has the editor's properties, events and method, and three attributes of its own:

| Name | What it does |
| --- | --- |
| `value` | The email the Shell shows, as on `<mail-quilt>`. With `save-key`, a saved email opens instead of the first one you set. With no `value` and nothing saved, the editor is empty and the export buttons say there's no email to export. |
| `uploadImage` | As on `<mail-quilt>`. The Shell passes it to the editor inside. |
| `heading` | The text in the header. It's "Email" when unset. |
| `actions` | The buttons to show, by name and separated by spaces: `import-json`, `export-json` and `export-html`. Leave it out to show all three. |
| `save-key` | Where the email is kept in the browser, as the `saveKey` property. Use one for each email and each person. Leave it out to store nothing. [Saving](./shell#saving) says how it works. |
| `mq-change` | Fired after every change, including an import. The new email is in `event.detail.document`. |
| `mq-error` | Fired when the editor refuses an email you set as `value`. The reason is in `event.detail.reason`, and the message bar shows it too. |
| `exportHtml()` | Returns a promise of the email's HTML, as on `<mail-quilt>`. |

## React

`@mailquilt/react` has two components, which render the same elements:

| Component | Props |
| --- | --- |
| `MailQuilt` | `value`, `onChange`, `onError`, `uploadImage` and `ref`. |
| `MailQuiltShell` | The same, and `heading`, `actions` and `saveKey`. `actions` is an array of names, such as `["export-html"]`. |

- `value` is the email to open. `onChange` gets the new email after every change, and `onError` gets the reason when the editor refuses one, or when the editor's code can't load. `onError` is always listening in time.
- `uploadImage` is the editor's property, which the component sets on the element once the editor has loaded.
- `ref` gives you the element once the editor has loaded, so you can call `exportHtml()`.
- Other props go to the element: `aria-*` attributes, React's events such as `onKeyDown`, and `className`, `hidden`, `id`, `inert`, `lang`, `role`, `slot`, `style`, `suppressHydrationWarning` and `title`.
- On the server, each component renders its empty element, and the editor loads in the browser.

`@mailquilt/react` needs React 19. The [React](./react) and [Next.js](./nextjs) pages show both components in use.

## TypeScript

| Type | From | What it is |
| --- | --- | --- |
| `BlocksDocument` | `@mailquilt/core`, `@mailquilt/editor` and `@mailquilt/react` | An email, as the [document format](./document-format) describes it. |
| `Block`, `Row`, `Column`, `EmailSettings` | `@mailquilt/core` | The parts of an email, as the [document format](./document-format) describes them. A `Block`'s `props` are its type's. |
| `BlockType` | `@mailquilt/core` | One of the Block types, as in `BLOCK_TYPES`. |
| `RichTextDocument`, `RichTextParagraph`, `RichTextText`, `RichTextHardBreak`, `RichTextMergeTag`, `RichTextMark` | `@mailquilt/core` | A Text or Heading Block's [rich text](./document-format#rich-text), and its parts. |
| `Command`, `RowLayout` | `@mailquilt/core` | One of the [Commands](./change-emails-in-code#commands), and one of the layouts in `ROW_LAYOUTS`. |
| `Operation` | `@mailquilt/core` | A record of one change, as [`subscribe()`](./change-emails-in-code#listening-for-changes) gives it to you. |
| `Editor` | `@mailquilt/core` | What `createEditor()` returns. |
| `ApplyOptions`, `ApplyResult`, `RefusalCode` | `@mailquilt/core` | What `apply()` takes as its second argument, what it returns, and the [`code`](./change-emails-in-code#commands) of a refusal. |
| `LoadResult` | `@mailquilt/core` | What `loadDocument()` returns: the email, or the reason it was refused. |
| `MailQuilt`, `MailQuiltShell` | `@mailquilt/editor` | The classes of `<mail-quilt>` and `<mail-quilt-shell>`, for a type or `instanceof`. Importing the package registers them, and `querySelector("mail-quilt")` already returns a `MailQuilt`. |
| `MailQuiltChangeEvent` | `@mailquilt/editor` | The `mq-change` event. |
| `MailQuiltErrorEvent` | `@mailquilt/editor` | The `mq-error` event. |
| `MailQuiltElement`, `MailQuiltShellElement` | `@mailquilt/react` | The elements a `ref` gives you: `MailQuilt` and `MailQuiltShell` under the names React uses. |
| `MailQuiltProps`, `MailQuiltShellProps` | `@mailquilt/react` | The components' props. |
| `ShellAction` | `@mailquilt/editor` and `@mailquilt/react` | One of the Shell's button names. |
| `HostAppProperties` | `@mailquilt/editor` and `@mailquilt/react` | The properties through which your app gives the editor what it can't do itself, such as `uploadImage`. |

`addEventListener` on the elements knows `mq-change` and `mq-error` by name, so their events are typed without a cast.

## CSS parts

The frame around the editor, with its corners and its 1px ring, is the `frame` part. Style it with `mail-quilt::part(frame)`, such as `border-radius: 0` for an editor that fills a panel edge to edge. When the editor is narrower than {{editor-min-width}} pixels, the notice it shows instead of the canvas is the `frame` part too, so what you give the frame, such as a height or corners, applies to the notice. In the Shell, the frame is the Shell's own, the `frame` part of `<mail-quilt-shell>`, and the editor inside draws none. Style it with `mail-quilt-shell::part(frame)`. The Shell's header and message bar are parts too, which [Customizing it](./shell#customizing-it) lists.

Colors, spacing, corners and the font are [theme tokens](./theme-tokens), not parts.

## Content Security Policy

The editor works under a policy that blocks inline styles, such as `style-src 'self'`. Only Preview needs `'unsafe-inline'` in `style-src`:

```text
Content-Security-Policy: style-src 'self' 'unsafe-inline'
```

Preview shows the email in a sandboxed iframe, which follows your page's policy, and emails rely on inline styles. Without it, Preview shows the email without its styling. The canvas and `exportHtml()` aren't affected, and the exported HTML is unchanged.

The canvas and Preview show each Image Block from its URL, so if your policy has `img-src`, or a `default-src` without one, it has to allow the sites your emails' images are on. To allow any image over HTTPS:

```text
Content-Security-Policy: img-src 'self' https:
```

An image it blocks doesn't show on the canvas or in Preview, and the exported HTML is unchanged. The editor's own icons and arrows are part of the page, so it needs no other image source, such as `data:`.

With [`uploadImage`](./upload-images), the editor makes no request of its own. Whatever your function fetches, such as your storage's upload URL, has to be allowed by `connect-src`, and the URL it returns by `img-src`.

A page using the [CDN build](./html) also needs `script-src` to allow the folder the build is in, because the build is several files. The path must end in `/`:

```text
Content-Security-Policy: script-src 'self' https://cdn.jsdelivr.net/npm/@mailquilt/editor@0.2.0/dist/cdn/
```

If it allows only `dist/cdn/index.js`, the editor doesn't load. An inline script like the one in the [HTML example](./html) also needs a nonce or hash, or you can move it into a file of your own.
