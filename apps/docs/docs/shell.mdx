`<mail-quilt>` is only the editor. Around it, your app still needs somewhere to export the email, somewhere to show why an email was refused, and a way to keep the person's work. `<mail-quilt-shell>` is all of that in one element: the editor, with a header above it and a message bar between them.

## Variants

| Variant | What the header has |
| --- | --- |
| `simple`, the default | The heading and an **Export HTML** button. |
| `advanced` | Everything in Simple, plus **Import JSON** and **Export JSON**. |

**Export HTML** downloads the email as `email.html`, ready to send. **Export JSON** downloads it as `email.json`, the [document format](./document-format) the editor saves. **Import JSON** opens a `.json` file. If the editor refuses it, the message bar says why and the current email stays.

The message bar shows emails the editor refuses, exports that fail and saves that fail. Screen readers announce each message. The [Playground](./playground) is the Advanced variant.

Importing `@mailquilt/editor` registers both `<mail-quilt>` and `<mail-quilt-shell>`. On a page with no build step, load the CDN build as the [quick start](./quick-start#without-a-bundler) shows. It registers both too.

The Shell fills the width and height of the space you give it, and the editor takes everything below the header. If the email is longer than that, the editor scrolls inside the Shell.

## Saving

With `save-key`, the Shell keeps the email in the browser's `localStorage` under that key:

- When the Shell opens, an email saved under the key opens instead of `value`. `value` is the email to start from when nothing is saved yet.
- If the saved email can't be opened, the message bar says why and `value` opens instead. The saved email stays as it is until the person changes something, so nothing is lost by opening the page.
- Each change is saved under the key. If the browser can't save, because storage is blocked or full, the message bar says so. In the Advanced variant, it suggests Export JSON instead.

Pick a key no other app on the same origin uses, such as one starting with your app's name.

Without `save-key`, the Shell stores nothing. Save the email yourself from `mq-change`, as the [quick start](./quick-start) does. `mq-change` fires with or without `save-key`, so you can keep the email in the browser and on your server too.

## The Shell's API

| Name | What it does |
| --- | --- |
| `value` | The email the Shell shows, as on `<mail-quilt>`. With `save-key`, a saved email opens instead of the first one you set. |
| `variant` | `"simple"`, the default, or `"advanced"`. The attribute shows the current variant. |
| `heading` | The text in the header. It defaults to "Email". |
| `save-key` | Where the email is kept in the browser, as the `saveKey` property. Leave it out to store nothing. |
| `mq-change` | Fired after every change, including an import. The new email is in `event.detail.document`. |
| `mq-error` | Fired when the editor refuses an email you set as `value`. The reason is in `event.detail.reason`, and the message bar shows it too. |
| `exportHtml()` | Returns a promise of the email's HTML, as on `<mail-quilt>`. |

`value`, `mq-change`, `mq-error` and `exportHtml()` follow the rules the [quick start](./quick-start#the-editors-api) describes, including when to listen for `mq-error`.

In React, these are the `value`, `variant`, `heading`, `saveKey`, `onChange` and `onError` props, and `exportHtml()` on the `ref`.

The Shell draws its header and messages from the same [theme tokens](./theme-tokens) as the editor. Set them on `<mail-quilt-shell>`, and the editor inside uses them too.

## Shell or `<mail-quilt>`?

Use the Shell when the editor is a page of its own and its header can be the page's controls. It gets an editor page working with a few lines, and a refused email or a failed save always reaches the person.

Use `<mail-quilt>` on its own when the editor sits inside a page your app already lays out, such as beside a form with the email's subject and recipients, or when you want your own buttons and messages. The Shell's header has no room for buttons of your own.
