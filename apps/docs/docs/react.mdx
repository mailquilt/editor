`@mailquilt/react` puts the editor in a React app as two components: `MailQuilt`, the editor, and `MailQuiltShell`, a whole editor page. Mail Quilt's tests build the code on this page in a Vite app with React 19, and again with React 18, type-check it, and run it in a browser, so it works as written. For Next.js, see the [Next.js](./nextjs) page.

```package-install
npm install @mailquilt/react
```

`@mailquilt/react` works with React 18 and 19, and it installs the editor for you.

Render `<Editor />` wherever the editor goes, such as from your `main.tsx`.

- `value` opens an email, and `onChange` gets the new email after every change. Keep it in state, as here, and pass it back as `value`.
- `onError` gets the reason when the editor refuses an email, or when its code can't load. It's always listening in time, so nobody is left looking at an empty editor.
- `ref` gives you the `<mail-quilt>` element once the editor has loaded, so you can call `exportHtml()`.
- `starterEmail` is the email to open when nothing is saved yet. Your app can open one it already has, or the [example email](./document-format#example), which has a Block of each type.

This example keeps the email in `localStorage` so it runs on its own. In your app, send each email to your server from `onChange` instead, as [Save emails to your server](./save-emails) shows, and don't set `value` from the server's answers.

## Image uploads

Pass `uploadImage` to let people upload images to your storage, from an Upload image button in the Image settings, or by dropping or pasting image files on the email. [Upload images](./upload-images) shows a function that does it:

```tsx
<MailQuilt onChange={setEmail} uploadImage={uploadImage} value={email} />
```

## Merge Tags

Pass `mergeTags` with your app's tags, and typing `{{` in text, or in a setting that holds text or a URL, opens a list of them to pick from. The format bar gets a Merge Tag button too. [Merge Tags](./api#merge-tags) says how the list works:

```tsx
const mergeTags = [
  { name: "first_name", label: "First name" },
  { name: "company" },
];

<MailQuilt mergeTags={mergeTags} onChange={setEmail} value={email} />;
```

A new array at each render is fine. The editor redraws its labels only when a tag in it changes.

## Social icons

A Social Block's icons load from jsDelivr unless you serve them yourself. Pass `socialIconsUrl` with the URL of a folder in your storage that holds a copy of the renderer's icons, and the canvas, Check and export load them from there. [Social icons](./social-icons) says how:

```tsx
<MailQuilt
  onChange={setEmail}
  socialIconsUrl="https://cdn.example.com/mail-icons/"
  value={email}
/>
```

## Props

`MailQuilt` takes `value`, `onChange`, `onError`, `uploadImage`, `fonts`, `mergeTags`, `starterEmails`, `savedRows`, `socialIconsUrl` and `ref`. `MailQuiltShell` takes those, and `heading`, `actions` and `saveKey`. Other props, such as `className`, `style` and `aria-label`, go to the element. The [editor's API](./api#react) lists them all, with their types.
