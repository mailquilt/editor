`@mailquilt/react` puts the editor in a React app as two components: `MailQuilt`, the editor, and `MailQuiltShell`, a whole editor page. Mail Quilt's tests build the code on this page in a Vite app with React 19, type-check it, and run it in a browser, so it works as written. For Next.js, see the [Next.js](./nextjs) page.

```package-install
npm install @mailquilt/react
```

`@mailquilt/react` needs React 19, and it installs the editor for you.

Render `<Editor />` wherever the editor goes, such as from your `main.tsx`.

- `value` opens an email, and `onChange` gets the new email after every change. Keep it in state, as here, and pass it back as `value`.
- `onError` gets the reason when the editor refuses an email, or when its code can't load. It's always listening in time, so nobody is left looking at an empty editor.
- `ref` gives you the `<mail-quilt>` element once the editor has loaded, so you can call `exportHtml()`.
- `starterEmail` is the email to open when nothing is saved yet. Your app can open one it already has, or the [example email](./document-format#example), which has a Block of each type.

This example keeps the email in `localStorage` so it runs on its own. In your app, send each email to your server from `onChange` instead, as [Save emails to your server](./save-emails) shows, and don't set `value` from the server's answers.

## Image uploads

Pass `uploadImage` to let people upload images to your storage, from an Upload image button in the Image settings. [Upload images](./upload-images) shows a function that does it:

```tsx
<MailQuilt onChange={setEmail} uploadImage={uploadImage} value={email} />
```

## Props

`MailQuilt` takes `value`, `onChange`, `onError`, `uploadImage` and `ref`. `MailQuiltShell` takes those, and `heading`, `actions` and `saveKey`. Other props, such as `className`, `style` and `aria-label`, go to the element. The [editor's API](./api#react) lists them all, with their types.
