This page puts the editor in a Next.js app that uses the App Router, and renders the email's HTML on the server. The Pages Router hasn't been tested. Mail Quilt's tests build every file on this page in a Next.js 16 app with React 19, open it in a browser, and post an email to the Route Handler, so the code works as written.

```bash
npm install @mailquilt/react @mailquilt/renderer
```

`@mailquilt/react` needs React 19. `@mailquilt/renderer` is only for the [Route Handler](#render-the-html-on-the-server), so leave it out if you export HTML in the browser.

The page that shows it can stay a Server Component:

<include meta='title="app/page.tsx"'>./_nextjs/app/page.tsx</include>

- **There's no `next/dynamic` to add.** On the server, `MailQuilt` renders an empty `<mail-quilt>`, and the editor loads in the browser.
- **`onError` is always listening in time.** If the editor refuses the email you pass, `onError` hears why, so nobody is left looking at an empty editor.
- **Save to your server from `onChange`.** This example saves in the browser so it runs on its own. In your app, send each email to your server instead, as [Save emails to your server](./save-emails) shows, and don't set `value` from the server's answers.

## Render the HTML on the server

Store the JSON from `onChange`, and make the HTML when you send. A Route Handler can do it with the [renderer](./render-on-a-server), which loads no editor code:

<include meta='title="app/email-html/route.ts"'>
  ./_nextjs/app/email-html/route.ts
</include>

- **It runs in the Node.js runtime**, which is the default for Route Handlers. The renderer needs Node 22 or later. It hasn't been tested in the Edge runtime.
- **A refused email gets a 422** with the renderer's reason, such as an email saved by a newer version of Mail Quilt. So does a body that isn't JSON.
- **As written, anyone who can reach this route can render any email they post.** In your app, check who's asking, or load the email from your own storage by its ID rather than from the request.

MJML, the library that writes the HTML, loads the first time a request renders an email.

## Content Security Policy

If your app sets a Content Security Policy, Preview needs `'unsafe-inline'` in `style-src`, and `img-src` has to allow the sites your emails' images are on. [Content Security Policy](./api#content-security-policy) explains why, and what happens without them.
