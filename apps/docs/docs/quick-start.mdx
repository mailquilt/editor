The editor is a Web Component, so it works in any framework, or none. In an app with a bundler, install it and import it, and `<mail-quilt>` works like any other HTML element. Mail Quilt's tests build this code with Vite and run it in a browser, so it works as written.

```package-install
npm install @mailquilt/editor
```

Importing `@mailquilt/editor` registers the `<mail-quilt>` element. MJML, the library that turns an email into HTML, is large, so it only loads the first time someone opens Preview or you call `exportHtml()`.

The page opens an email, saves every change in the browser, shows the reason if the editor refuses an email, and exports the email as HTML. `starterEmail` is the email to open when nothing is saved yet. Your app can open one it already has, or the [example email](./document-format#example), which has a Block of each type. In your app, save each email to your server instead, as [Save emails to your server](./save-emails) shows.

If the editor will be a page of its own, the [Shell](./shell) gives you that page ready-made: the editor with a header, Export and Import buttons, messages and saving in the browser. Importing `@mailquilt/editor` registers it too.

## Two things to get right

- **Only pass back the latest email.** An older one counts as a different email, so it opens and clears undo history. If you save each change to a server, don't set `value` from each response, or a slow response could replace what someone typed since.
- **Listen for `mq-error` before the editor can refuse anything.** It fires just after the code that sets `value` finishes, and it isn't fired again. A listener added before setting `value`, as in the examples, or straight after it, hears it. One added later, such as in a React `useEffect`, misses it, and people see an empty editor with no explanation. The React component's `onError` is always listening in time.
