Mail Quilt saves an email as a JSON document: Rows hold Columns, and Columns hold Blocks. This is the document `mq-change` gives you and `value` takes, so you can store it anywhere JSON goes. In TypeScript, it's the `BlocksDocument` type, exported by `@mailquilt/core`, `@mailquilt/editor` and `@mailquilt/react`.

The editor never repairs a document. If one doesn't match this format, the editor refuses it, keeps the email it had, and fires `mq-error` with the reason. A field the editor doesn't know is refused too, rather than dropped, so your next save can't lose it.

## Document

| Field | Value |
| --- | --- |
| `kind` | Always `"blocks"`. |
| `version` | The format version, a whole number. The current version is `3`, and a newer one is refused. A document saved in an older version is upgraded as it loads, as [versions](#versions) describes. |
| `settings` | The [email settings](#email-settings). |
| `rows` | A list of [Rows](#row), top to bottom. It can be empty. |

## Versions

Each version of the format, and how a document saved in the one before is upgraded as it loads. The export of an upgraded email doesn't change.

| Version | Saved by | What it added |
| --- | --- | --- |
| `1` | Mail Quilt 0.1.0 | The first version. |
| `2` | Mail Quilt 0.2.0 | Stricter colors and URLs. A version 1 email gets a plain space in a color where it has another space after a comma, such as a tab, and `https:` in place of `httpſ:` at the start of a link or image URL. |
| `3` | Mail Quilt 0.3.0 | The [`mergeTag`](#merge-tags-in-text) node in rich text. Each Merge Tag that sits whole in one piece of text becomes a node, with that text's marks. A tag split across pieces with different marks, such as `{{first` in bold and `_name}}` not, stays text. Bulleted and numbered [Lists](#lists) in a Text Block, which no older email has. |

An email saved by a newer version can't be opened by a package that only knows an older one.

## Email settings

| Field | Value |
| --- | --- |
| `width` | Required. The email's width, a whole number of pixels from 1 to 1200. |
| `backgroundColor` | Required. A [color](#colors). |
| `fontFamily` | Required. A CSS font list, such as `"Arial, Helvetica, sans-serif"`. It can hold only the letters A to Z, digits, spaces, hyphens, underscores, commas and quotes, and each quote has to close. The settings panel offers Arial, Courier New, Georgia, Tahoma, Times New Roman and Verdana. |
| `preheader` | Optional. The short text inboxes show after the subject. |
| `language` | Optional. The email's language. A new language has to be a code such as `en` or `pt-BR`, or one [Merge Tag](#merge-tags) such as `{{language}}` that your sending tool fills with each person's code, and `updateEmailSettings` refuses anything else, from the settings panel or your code. A saved document loads with any text here, and sending it back unchanged isn't refused, so an email with a bad value can still be opened and fixed. |

## Row

| Field | Value |
| --- | --- |
| `id` | An [ID](#ids). |
| `props` | An object with one optional field, `backgroundColor`, a [color](#colors). |
| `columns` | A list of 1 to 4 [Columns](#column), left to right. |

## Column

| Field | Value |
| --- | --- |
| `id` | An [ID](#ids). |
| `width` | A percentage of the Row, from 1 to 100, so a Column is at least 1% wide. The widths of a Row's Columns add up to 100. The editor's layouts use `100`, `50`/`50`, `33`/`67`, `67`/`33`, `33.33`/`33.33`/`33.34` and four Columns of `25`. Other widths load, but the side panel shows none of its layouts as chosen for that Row. |
| `props` | Always an empty object, `{}`. |
| `blocks` | A list of [Blocks](#blocks), top to bottom. It can be empty. |

## Blocks

Every Block has an `id`, which is an [ID](#ids), a `type` from the list below, and `props` for that type. A field marked optional can be left out, and the default is what the email shows without it.

### Text

`"type": "text"`

| Prop | Value |
| --- | --- |
| `content` | Required. [Rich text](#rich-text), which can have [Lists](#lists). |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |
| `color` | Optional. A [color](#colors). Defaults to `#000000`. |
| `fontSize` | Optional. A whole number of pixels from 1 to 200. Defaults to `16`. |

### Heading

`"type": "heading"`

| Prop | Value |
| --- | --- |
| `level` | Required. `1`, `2` or `3`. |
| `content` | Required. [Rich text](#rich-text) of paragraphs only, without [Lists](#lists). A Heading exports as one heading, however many lines it has. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |
| `color` | Optional. A [color](#colors). Defaults to `#000000`. |
| `fontSize` | Optional. A whole number of pixels from 1 to 200. Defaults to `32`, `24` or `20` for levels 1, 2 and 3. |

### Image

`"type": "image"`

| Prop | Value |
| --- | --- |
| `src` | Optional. The image's URL, starting with `https:` or `http:`, or a [Merge Tag](#merge-tags) such as `{{logo_url}}`. A new Image has none until someone adds one, and an Image without one is left out of the exported HTML. |
| `alt` | Optional. What a screen reader says, and what shows if images are off. |
| `width` | Optional. A whole number of pixels, 1 or more. Without it, the image fills the Column, and it never grows wider than the Column. |
| `href` | Optional. A [link](#links). A linked Image needs `alt` text that isn't blank, because the alt text is all that names the link. |

### Button

`"type": "button"`

| Prop | Value |
| --- | --- |
| `label` | Required. The Button's text, as plain text that isn't blank. |
| `href` | Optional. A [link](#links). |
| `backgroundColor` | Optional. A [color](#colors) that isn't `rgba()`, because a see-through one would come out darker than it should. Defaults to `#2563eb`. |
| `color` | Optional. The text's [color](#colors). Defaults to `#ffffff`. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |

### Divider

`"type": "divider"`

| Prop | Value |
| --- | --- |
| `color` | Optional. A [color](#colors). Defaults to `#d4d4d8`. |
| `thickness` | Optional. A whole number of pixels from 1 to 100. Defaults to `1`. |

### Spacer

`"type": "spacer"`

| Prop | Value |
| --- | --- |
| `height` | Optional. A whole number of pixels from 1 to 1000. Defaults to `24`. |

## Rich text

Text and Heading Blocks store their text as a limited form of [ProseMirror](https://prosemirror.net) JSON, the format [Tiptap](https://tiptap.dev) uses too:

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "Hello, " },
        {
          "type": "mergeTag",
          "attrs": { "name": "first_name" },
          "marks": [{ "type": "bold" }]
        },
        { "type": "hardBreak" },
        {
          "type": "text",
          "text": "Visit us",
          "marks": [
            { "type": "link", "attrs": { "href": "https://example.com" } }
          ]
        }
      ]
    }
  ]
}
```

- `doc` holds one or more paragraphs and, in a Text Block, [Lists](#lists).
- A `paragraph` has an optional `content` list, which leaves it empty when it's missing.
- A `text` item has `text`, which can't be empty, and optional `marks`.
- A `hardBreak` is a line break inside a paragraph. It can have `marks` too.
- A `mergeTag` is a [Merge Tag](#merge-tags-in-text), with its name in `attrs.name`. It can have `marks` too.
- The marks are `bold`, `italic`, `underline` and `link`. A link mark has `attrs.href`, which is a [link](#links). A piece of text can't have the same mark twice.

Nothing else is accepted, such as headings inside text, colors or other marks.

### Lists

A Text Block can hold bulleted and numbered Lists between its paragraphs, one level deep, with one paragraph in each item. A Heading can't.

```json
{
  "type": "bulletList",
  "content": [
    {
      "type": "listItem",
      "content": [
        { "type": "paragraph", "content": [{ "type": "text", "text": "One" }] }
      ]
    },
    { "type": "listItem", "content": [{ "type": "paragraph" }] }
  ]
}
```

- A `bulletList` is bulleted and an `orderedList` is numbered. They have the same shape, and neither has `attrs`, so a numbered List always starts at 1.
- A List holds one or more `listItem`s.
- A `listItem` holds exactly one [`paragraph`](#rich-text), which can have line breaks, marks and Merge Tags. A List can't go inside an item.
- The export writes a List as `<ul>` or `<ol>`, indented by a margin of 1.5 times the Block's font size, and each item with the same line height as a paragraph.

### Merge Tags in text

In text, a [Merge Tag](#merge-tags) is a node of its own, so the editor treats it as one unit: Backspace removes it whole, and the cursor can't go inside it.

```json
{ "type": "mergeTag", "attrs": { "name": "first_name" } }
```

- `name` is what goes between the braces, exactly as written, spaces and all, so tags such as `{{#if vip}}` and `{{ user.name | upcase }}` keep your sending tool's syntax. It can be any text that isn't empty and has no `{` or `}`. Mail Quilt doesn't check that the name is one your sending tool knows.
- The export writes the node as `{{first_name}}`.
- A tag typed in the editor becomes a node when its `}}` is typed, and so does each tag in pasted text. A mark on part of its text goes on all of it.
- A `{{…}}` left in a `text` item, such as one split across pieces with different marks, stays text and exports as written, until it's edited in the editor.

## Values

### IDs

An ID is a string that isn't empty. Every Row, Column and Block in a document needs a different one. The editor creates random IDs for what it adds.

### Colors

A color is written as `#rgb`, `#rrggbb`, `rgb()` or `rgba()`, such as `#f00`, `#ff0000`, `rgb(255, 0, 0)` or `rgba(255, 0, 0, 0.5)`. Named colors such as `red` are refused. These are the formats MJML accepts, so every email that opens can also be exported. That means at most one space after each comma, and an alpha with its leading 0, as in `0.5` rather than `.5`. A channel can have up to three digits, and one past 255 shows as 255.

### Links

A link starts with `https:`, `http:`, `mailto:` or `tel:`, or with a [Merge Tag](#merge-tags) such as `{{cta_url}}`. Other schemes, such as `javascript:`, and relative URLs are refused.

### Merge Tags

A Merge Tag such as `{{first_name}}` can go anywhere in text, as a [node](#merge-tags-in-text), and in every setting that holds text or a URL, such as a Button's label, an Image's alt text and the email's preheader. In a link or image URL it can go at the start or after it, as in `https://example.com/u/{{user_id}}`, and the language can be one Merge Tag as its whole value. Mail Quilt keeps it as written in the exported HTML, so your sending tool can fill it in. In a URL that starts with a Merge Tag, no colon can come between the tag and the first `/`, `?` or `#`, so `{{base}}/path` is a link but `{{x}}javascript:` isn't. That means a tag followed by a scheme is refused too, so a tag can't wrap a whole URL, as in `{{#if vip}}https://example.com{{/if}}`.

Mail Quilt escapes any `&`, `<` or `>` in a Merge Tag, and any `"` too in a link or image URL or an Image's alt text, such as `&` to `&amp;`. Your sending tool sees the escaped tag, so keep tags to names, such as `{{cta_url}}`.
