Mail Quilt saves an email as a JSON document: Rows hold Columns, and Columns hold Blocks. This is the document `mq-change` gives you and `value` takes, so you can store it anywhere JSON goes. In TypeScript, it's the `BlocksDocument` type, exported by `@mailquilt/core`, `@mailquilt/editor` and `@mailquilt/react`.

The editor never repairs a document. If one doesn't match this format, the editor refuses it, keeps the email it had, and fires `mq-error` with the reason. A field the editor doesn't know is refused too, rather than dropped, so your next save can't lose it.

## JSON Schema

To check an email in your own code, or have your code editor check a file as you write it, use the format's [JSON Schema](/schema/v4.json). From version 4 on, each version of the format has a schema at an address of its own, such as `https://editor.mailquilt.com/schema/v4.json`, which stays when a newer version comes. `@mailquilt/core` includes the one for the version it saves, as `@mailquilt/core/schema.json`. It's written for JSON Schema draft 2020-12, whose patterns are JavaScript regular expressions, so use a validator that reads them as JavaScript does.

The schema is made from the checks the editor runs, so a version 4 email the schema refuses, the editor refuses too. A few rules compare one value with another, which JSON Schema can't express, so only the editor, and `loadDocument` in `@mailquilt/core`, checks them:

- Every Row, Column and Block has an [ID](#ids) of its own.
- A Row's Column widths add up to 100.
- Text has each mark at most once.
- A Social Block links each network once.
- A linked Image has alt text.
- A decorative Image has neither alt text nor a link.

An email can't name its schema in a `$schema` field, because a field the format doesn't know is refused. Tell your code editor which files the schema is for in its settings instead.

## Document

| Field | Value |
| --- | --- |
| `kind` | Always `"blocks"`. |
| `version` | The format version, a whole number. The current version is `4`, and a newer one is refused. A document saved in an older version is upgraded as it loads, as [versions](#versions) describes. |
| `settings` | The [email settings](#email-settings). |
| `rows` | A list of [Rows](#row), top to bottom. It can be empty. |

## Versions

Each version of the format, and how a document saved in the one before is upgraded as it loads. The export of an upgraded email doesn't change.

| Version | Saved by | What it added |
| --- | --- | --- |
| `1` | Mail Quilt 0.1.0 | The first version. |
| `2` | Mail Quilt 0.2.0 | Stricter colors and URLs. A version 1 email gets a plain space in a color where it has another space after a comma, such as a tab, and `https:` in place of `httpſ:` at the start of a link or image URL. |
| `3` | Mail Quilt 0.3.0 | The [`mergeTag`](#merge-tags-in-text) node in rich text. Each Merge Tag that sits whole in one piece of text becomes a node, with that text's marks. A tag split across pieces with different marks, such as `{{first` in bold and `_name}}` not, stays text. Bulleted and numbered [Lists](#lists) in a Text Block, a Row's [padding and phone settings](#row), and the [Social](#social) Block, which no older email has. |
| `4` | Mail Quilt 0.4.0 | The [Email style](#email-style), every Block's [Box](#box), a [Column](#column)'s settings, [showing on a device](#showing-on-a-device), [Phone values](#phone-values), and the [Menu](#menu) and [Video](#video) Blocks, which no older email has. A Row's `hideOnPhone` is gone: a version 3 Row with `hideOnPhone: true` loads with `showOn: "desktop"`, and one with `false` without either. Nothing else changes but the version. |

An email saved by a newer version can't be opened by a package that only knows an older one.

## Email settings

| Field | Value |
| --- | --- |
| `width` | Required. The email's width, a whole number of pixels from 1 to 1200. |
| `backgroundColor` | Required. The page's [color](#colors), around the email. |
| `fontFamily` | Required. The body font, for text, Buttons and, unless the [Email style](#email-style) sets one, Headings. A CSS font list, such as `"Arial, Helvetica, sans-serif"`. It can hold only the letters A to Z, digits, spaces, hyphens, underscores, commas and quotes, and each quote has to close. The editor offers Arial, Courier New, Georgia, Tahoma, Times New Roman and Verdana. |
| `preheader` | Optional. The short text inboxes show after the subject. |
| `language` | Optional. The email's language. A new language has to be a code such as `en` or `pt-BR`, or one [Merge Tag](#merge-tags) such as `{{language}}` that your sending tool fills with each person's code, and `updateEmailSettings` refuses anything else, from the editor or your code. A saved document loads with any text here, and sending it back unchanged isn't refused, so an email with a bad value can still be opened and fixed. |
| `style` | Optional. The [Email style](#email-style). |

In the editor, `width`, `preheader` and `language` are in the Selection bar with nothing selected. `backgroundColor` and `fontFamily` are Page and Body in Style, beside the Email style.

## Email style

The look every Block in the email uses unless it sets its own. A Block takes its own value first, then the Email style's, then the built-in look, so changing the Email style never changes a value a person set on a Block. Every field is optional, and one left out gives the built-in look.

| Field | Value |
| --- | --- |
| `emailBackgroundColor` | A [color](#colors), behind every Row that doesn't set its own. Without it, the page's color shows through. |
| `textColor` | A [color](#colors), for Text Blocks and Headings. Defaults to `#000000`. |
| `linkColor` | A [color](#colors), for links in text. Defaults to the text's color. A Text Block or Heading that sets its own `color` keeps its links in that color, as it was chosen for that Block's background. |
| `headingFontFamily` | A CSS font list, as `fontFamily` takes, for Headings. Defaults to the body font, `fontFamily`. |
| `heading1FontSize`, `heading2FontSize`, `heading3FontSize` | A whole number of pixels from 1 to 200, for Headings of that level. Default to `32`, `24` and `20`. |
| `textFontSize` | A whole number of pixels from 1 to 200, for Text Blocks and Buttons' labels. Defaults to `16`. |
| `buttonBackgroundColor` | A [color](#colors) that isn't `rgba()`, for Buttons. Defaults to `#2563eb`. |
| `buttonBorderRadius` | A whole number of pixels from 0 to 100, for Buttons' corners. Defaults to `3`. |

```json
{
  "textColor": "#2b1d14",
  "linkColor": "#b5652b",
  "headingFontFamily": "Georgia, 'Times New Roman', serif",
  "buttonBorderRadius": 0
}
```

In the editor, every field is in Style, where each can be set, or cleared back to its default. Button corners there are Square, `0`, Rounded, `8`, or Pill, `100`. `updateEmailStyle` changes some of its fields and leaves the rest, as [Change emails in code](./change-emails-in-code) shows.

## Row

| Field     | Value                                               |
| --------- | --------------------------------------------------- |
| `id`      | An [ID](#ids).                                      |
| `props`   | The Row's settings, below. Each is optional.        |
| `columns` | A list of 1 to 4 [Columns](#column), left to right. |

| Prop | Value |
| --- | --- |
| `backgroundColor` | Optional. A [color](#colors). |
| `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft` | Optional. The space inside the Row on that side, a whole number of pixels from 0 to 200. Defaults to `0`. The Row's Columns share the email's width less its left and right padding. |
| `showOn`, `phone` | Optional. The devices the Row shows on, and its padding's [Phone values](#phone-values), as below. |
| `stackOnPhone` | Optional. `false` keeps the Row's Columns side by side on phones, each at its share of the width. Defaults to `true`, which puts them one under another on screens under 480px wide. A Row with one Column looks the same either way, and its settings don't show it. |

## Column

| Field | Value |
| --- | --- |
| `id` | An [ID](#ids). |
| `width` | A percentage of the Row, from 1 to 100, so a Column is at least 1% wide. The widths of a Row's Columns add up to 100. The editor's layouts use `100`, `50`/`50`, `33`/`67`, `67`/`33`, `33.33`/`33.33`/`33.34` and four Columns of `25`. Other widths load, but the Selection bar shows none of its layouts as chosen for that Row. |
| `props` | The Column's settings, below. Each is optional. |
| `blocks` | A list of [Blocks](#blocks), top to bottom. It can be empty. |

| Prop | Value |
| --- | --- |
| `backgroundColor` | Optional. A [color](#colors). It fills the Column only as far down as its Blocks reach, as email clients draw it. Without it, the Row's color shows through. |
| `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft` | Optional. The space inside the Column on that side, a whole number of pixels from 0 to 200. Defaults to `0`. |
| `verticalAlign` | Optional. Where the Column sits in its Row when it's shorter than the Row: `"top"`, `"middle"` or `"bottom"`. Defaults to `"top"`. |
| `borderWidth`, `borderStyle`, `borderColor` | Optional. A [border](#borders) around the Column. |
| `phone` | Optional. Its padding's [Phone values](#phone-values). A Column shows wherever its Row does, so it has no `showOn`. |

## Showing on a device

A Block's or Row's `showOn` is `"desktop"`, to show it only on screens 480px wide and over, or `"phone"`, to show it only under 480px. Without it, it shows on every device. The email has both versions, and its styles hide one, so an email client that drops the styles shows what's for desktops on a phone too, and leaves out what's for phones, as [Tested email clients](./email-clients#showing-on-a-device-and-phone-values) says. Outlook on Windows never shows what's for phones.

```json
{ "showOn": "phone" }
```

## Phone values

A Block's, Row's or Column's `phone` holds a second value for some of its settings, used on screens under 480px wide. A setting it doesn't hold keeps its own value on phones. It can hold only these, and any other key is refused:

| In `phone` | On |
| --- | --- |
| `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft` | Every Block, Row and Column, as each one's padding. |
| `fontSize` | A [Text](#text) Block, a [Heading](#heading), a [Button](#button) and a [Menu](#menu), a whole number of pixels from 1 to 200. A Button has a font size only on phones. |
| `width` | An [Image](#image), a whole number of pixels from 1. It stops at its Column's width, as on a desktop. |

```json
{ "fontSize": 36, "phone": { "fontSize": 28, "paddingLeft": 8 } }
```

## Blocks

Every Block has an `id`, which is an [ID](#ids), a `type` from the list below, and `props` for that type and its [Box](#box). A field marked optional can be left out, and the default is what the email shows without it.

### Box

Every type of Block also takes these props, which set the box around its content. Each is optional. Every type takes [`showOn`](#showing-on-a-device) and [`phone`](#phone-values) too.

| Prop | Value |
| --- | --- |
| `paddingTop`, `paddingRight`, `paddingBottom`, `paddingLeft` | The space between the Block's edge and its content on that side, a whole number of pixels from 0 to 200. Defaults to `16`, or `0` for a [Spacer](#spacer). A [Social](#social) Block's icons keep half the space between them from its edge, so a padding less than that, `0` too, leaves them that far in. A [Menu](#menu)'s links do the same on its left and right. |
| `boxBackgroundColor` | A [color](#colors) behind the Block's content and padding. It's named apart from a Button's `backgroundColor`, which is the Button's own color. |
| `borderWidth`, `borderStyle`, `borderColor` | A [border](#borders) around the Block. |
| `borderRadius` | The Block's corners, a whole number of pixels from 0 to 100. On a [Button](#button), it shapes the Button itself, over the Email style's `buttonBorderRadius`. Outlook on Windows draws corners square, as [Tested email clients](./email-clients#boxes-and-columns) says. |

### Text

`"type": "text"`

| Prop | Value |
| --- | --- |
| `content` | Required. [Rich text](#rich-text), which can have [Lists](#lists). |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |
| `color` | Optional. A [color](#colors). Defaults to the [Email style](#email-style)'s `textColor`, or else `#000000`. |
| `fontSize` | Optional. A whole number of pixels from 1 to 200. Defaults to the Email style's `textFontSize`, or else `16`. |

### Heading

`"type": "heading"`

| Prop | Value |
| --- | --- |
| `level` | Required. `1`, `2` or `3`. |
| `content` | Required. [Rich text](#rich-text) of paragraphs only, without [Lists](#lists). A Heading exports as one heading, however many lines it has. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |
| `color` | Optional. A [color](#colors). Defaults to the [Email style](#email-style)'s `textColor`, or else `#000000`. |
| `fontSize` | Optional. A whole number of pixels from 1 to 200. Defaults to the Email style's size for its level, or else `32`, `24` or `20` for levels 1, 2 and 3. |

### Image

`"type": "image"`

| Prop | Value |
| --- | --- |
| `src` | Optional. The image's URL, starting with `https:` or `http:`, or a [Merge Tag](#merge-tags) such as `{{logo_url}}`. A new Image has none until someone adds one, and an Image without one is left out of the exported HTML. |
| `alt` | Optional. What a screen reader says, and what shows if images are off. |
| `width` | Optional. A whole number of pixels, 1 or more. Without it, the image fills the Column, and it never grows wider than the Column. |
| `href` | Optional. A [link](#links). A linked Image needs `alt` text that isn't blank, because the alt text is all that names the link. |
| `decorative` | Optional. `true` for an image that adds nothing to what the email says, such as a divider graphic, so a screen reader skips it. It exports with `alt=""`, can have neither `alt` nor `href`, and [`checkEmail`](./render-on-a-server#check-an-email-before-you-send) doesn't ask for its alt text. Defaults to `false`. |

### Button

`"type": "button"`

| Prop | Value |
| --- | --- |
| `label` | Required. The Button's text, as plain text that isn't blank. |
| `href` | Optional. A [link](#links). |
| `backgroundColor` | Optional. A [color](#colors) that isn't `rgba()`, because a see-through one would come out darker than it should. Defaults to the [Email style](#email-style)'s `buttonBackgroundColor`, or else `#2563eb`. |
| `color` | Optional. The text's [color](#colors). Defaults to `#ffffff`. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |

### Divider

`"type": "divider"`

| Prop | Value |
| --- | --- |
| `color` | Optional. A [color](#colors). Defaults to `#d4d4d8`. |
| `thickness` | Optional. A whole number of pixels from 1 to 100. Defaults to `1`. |

### Spacer

`"type": "spacer"`

| Prop | Value |
| --- | --- |
| `height` | Optional. A whole number of pixels from 1 to 1000. Defaults to `24`. |

### Social

`"type": "social"`

| Prop | Value |
| --- | --- |
| `links` | Required. The links, in the order their icons show, each with its `network` and `url`, below. Each network can be in the list once. A new Social Block has none. |
| `iconStyle` | Optional. `"color"`, each brand's own color, or `"white"`, for a dark background. Defaults to `"color"`. |
| `iconSize` | Optional. `32`, `40` or `48`, in pixels. Defaults to `32`. The gap between icons, and between lines of icons that wrap, is half that. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |

| Link field | Value |
| --- | --- |
| `network` | Required. `"facebook"`, `"instagram"`, `"linkedin"`, `"x"`, `"youtube"`, `"tiktok"`, `"pinterest"`, `"threads"`, `"bluesky"` or `"website"`. |
| `url` | Optional. A [link](#links). A link without one stays in the list, faded on the canvas, and is left out of the exported HTML. A Social Block none of whose links has one is left out too, as an Image without a `src` is. |

```json
{
  "links": [
    { "network": "instagram", "url": "https://instagram.com/example" },
    { "network": "website", "url": "{{site_url}}" }
  ],
  "iconStyle": "white",
  "align": "center"
}
```

Each icon is an image, with the network's name as its alt text. [Social icons](./social-icons) says where the images load from.

### Menu

`"type": "menu"`

A row of links, such as a website's main pages in a header or footer.

| Prop | Value |
| --- | --- |
| `links` | Required. The links, in the order they show, each with its `label` and `url`, below. A new Menu has none. |
| `align` | Optional. `"left"`, `"center"` or `"right"`. Defaults to `"left"`. |
| `color` | Optional. The links' [color](#colors). Defaults to the [Email style](#email-style)'s `textColor`, or else `#000000`. |
| `fontSize` | Optional. A whole number of pixels from 1 to 200. Defaults to the Email style's `textFontSize`, or else `16`. |
| `gap` | Optional. The space between links, a whole number of pixels from 1 to 100. Defaults to `24`. |

| Link field | Value |
| --- | --- |
| `label` | Optional. The words the link shows, as plain text that isn't blank. |
| `url` | Optional. A [link](#links). |

A link without a `label` or a `url` stays in the list, faded on the canvas, and is left out of the exported HTML. A Menu none of whose links has both is left out too, as an Image without a `src` is. The links sit on one line and wrap onto the next where they don't fit, as on a phone, without underlines.

```json
{
  "links": [
    { "label": "Shop", "url": "https://example.com/shop" },
    { "label": "Your orders", "url": "{{orders_url}}" }
  ],
  "align": "right",
  "fontSize": 13,
  "gap": 20
}
```

### Video

`"type": "video"`

A picture that links to a video, since email can't play one. Readers click it to watch the video where it is, such as on YouTube.

| Prop | Value |
| --- | --- |
| `url` | Optional. The video's [link](#links). |
| `thumbnail` | Optional. The picture's URL, starting with `https:` or `http:`, or a [Merge Tag](#merge-tags), as an [Image](#image)'s `src` is. In the editor, a YouTube link fills it in from YouTube's own thumbnail for the video, which someone can replace. |
| `alt` | Optional. What the picture shows. A screen reader says it for the link to the video, and it shows if images are off. |
| `play` | Optional. How the email shows it's a video: `"below"`, a line under the picture with a play mark and `label`; `"on"`, a play button on the picture, which is `playThumbnail`; or `"none"`, the picture alone. Defaults to `"below"`. |
| `playThumbnail` | Optional. A copy of the thumbnail with a play button drawn on it, as an image URL, which shows in its place while `play` is `"on"`. The editor draws it in the browser and uploads it through [`uploadImage`](./upload-images#a-videos-play-button). While `play` is `"on"` without one, the line shows instead. |
| `label` | Optional. The line's words, as plain text that isn't blank. Defaults to `"Watch the video"`. |
| `color` | Optional. The line's [color](#colors). Defaults to the [Email style](#email-style)'s `linkColor`, or else its `textColor`, or else `#000000`. The line's size and font are the Email style's text size and body font. |

A Video without both a `url` and a `thumbnail` is left out of the exported HTML, as an Image without a `src` is. The picture fills the Column, and the line sits centred under it. The play mark is a ▶ in a circle of the line's color, which Outlook on Windows draws square. A button laid over the picture would need either CSS that Outlook.com and Yahoo Mail drop, or a background image, which Mail Quilt doesn't write yet, so a play button on the picture is drawn into a copy of it instead.

```json
{
  "url": "https://www.youtube.com/watch?v=q8Ln2kXa_-9",
  "thumbnail": "https://i.ytimg.com/vi/q8Ln2kXa_-9/maxresdefault.jpg",
  "alt": "Our roaster tipping a batch of beans",
  "label": "Watch the roast"
}
```

## Rich text

Text and Heading Blocks store their text as a limited form of [ProseMirror](https://prosemirror.net) JSON, the format [Tiptap](https://tiptap.dev) uses too:

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "Hello, " },
        {
          "type": "mergeTag",
          "attrs": { "name": "first_name" },
          "marks": [{ "type": "bold" }]
        },
        { "type": "hardBreak" },
        {
          "type": "text",
          "text": "Visit us",
          "marks": [
            { "type": "link", "attrs": { "href": "https://example.com" } }
          ]
        }
      ]
    }
  ]
}
```

- `doc` holds one or more paragraphs and, in a Text Block, [Lists](#lists).
- A `paragraph` has an optional `content` list, which leaves it empty when it's missing.
- A `text` item has `text`, which can't be empty, and optional `marks`.
- A `hardBreak` is a line break inside a paragraph. It can have `marks` too.
- A `mergeTag` is a [Merge Tag](#merge-tags-in-text), with its name in `attrs.name`. It can have `marks` too.
- The marks are `bold`, `italic`, `underline` and `link`. A link mark has `attrs.href`, which is a [link](#links). A piece of text can't have the same mark twice.

Nothing else is accepted, such as headings inside text, colors or other marks.

### Lists

A Text Block can hold bulleted and numbered Lists between its paragraphs, one level deep, with one paragraph in each item. A Heading can't.

```json
{
  "type": "bulletList",
  "content": [
    {
      "type": "listItem",
      "content": [
        { "type": "paragraph", "content": [{ "type": "text", "text": "One" }] }
      ]
    },
    { "type": "listItem", "content": [{ "type": "paragraph" }] }
  ]
}
```

- A `bulletList` is bulleted and an `orderedList` is numbered. They have the same shape, and neither has `attrs`, so a numbered List always starts at 1.
- A List holds one or more `listItem`s.
- A `listItem` holds exactly one [`paragraph`](#rich-text), which can have line breaks, marks and Merge Tags. A List can't go inside an item.
- The export writes a List as `<ul>` or `<ol>`, indented by a margin of 1.5 times the Block's font size, and each item with the same line height as a paragraph.

### Merge Tags in text

In text, a [Merge Tag](#merge-tags) is a node of its own, so the editor treats it as one unit: Backspace removes it whole, and the cursor can't go inside it.

```json
{ "type": "mergeTag", "attrs": { "name": "first_name" } }
```

- `name` is what goes between the braces, exactly as written, spaces and all, so tags such as `{{#if vip}}` and `{{ user.name | upcase }}` keep your sending tool's syntax. It can be any text that isn't empty and has no `{` or `}`. Mail Quilt doesn't check that the name is one your sending tool knows.
- The export writes the node as `{{first_name}}`.
- A tag typed in the editor becomes a node when its `}}` is typed, and so does each tag in pasted text. A mark on part of its text goes on all of it.
- A `{{…}}` left in a `text` item, such as one split across pieces with different marks, stays text and exports as written, until it's edited in the editor.

## Values

### IDs

An ID is a string that isn't empty. Every Row, Column and Block in a document needs a different one. The editor creates random IDs for what it adds.

### Colors

A color is written as `#rgb`, `#rrggbb`, `rgb()` or `rgba()`, such as `#f00`, `#ff0000`, `rgb(255, 0, 0)` or `rgba(255, 0, 0, 0.5)`. Named colors such as `red` are refused. These are the formats MJML accepts, so every email that opens can also be exported. That means at most one space after each comma, and an alpha with its leading 0, as in `0.5` rather than `.5`. A channel can have up to three digits, and one past 255 shows as 255.

### Links

A link starts with `https:`, `http:`, `mailto:` or `tel:`, or with a [Merge Tag](#merge-tags) such as `{{cta_url}}`. Other schemes, such as `javascript:`, and relative URLs are refused.

### Borders

A border is drawn once it has a `borderWidth`, a whole number of pixels from 1 to 20. `borderStyle` is `"solid"`, `"dashed"` or `"dotted"`, and defaults to `"solid"`. `borderColor` is a [color](#colors), and defaults to `#000000`.

### Merge Tags

A Merge Tag such as `{{first_name}}` can go anywhere in text, as a [node](#merge-tags-in-text), and in every setting that holds text or a URL, such as a Button's label, an Image's alt text, a Social link's URL and the email's preheader. In a link or image URL it can go at the start or after it, as in `https://example.com/u/{{user_id}}`, and the language can be one Merge Tag as its whole value. Mail Quilt keeps it as written in the exported HTML, so your sending tool can fill it in. In a URL that starts with a Merge Tag, no colon can come between the tag and the first `/`, `?` or `#`, so `{{base}}/path` is a link but `{{x}}javascript:` isn't. That means a tag followed by a scheme is refused too, so a tag can't wrap a whole URL, as in `{{#if vip}}https://example.com{{/if}}`.

Mail Quilt escapes any `&`, `<` or `>` in a Merge Tag, and any `"` too in a link or image URL or an Image's alt text, such as `&` to `&amp;`. Your sending tool sees the escaped tag, so keep tags to names, such as `{{cta_url}}`.
