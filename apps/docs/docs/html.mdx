For a page with no build step, such as plain HTML or a template in Rails, Laravel or Django, load the editor's CDN build in a `<script type="module">`. There's nothing to install. Mail Quilt's tests load this page against the CDN build and run it in a browser, so the code works as written.

<include meta='title="index.html"'>./_quick-start/cdn/index.html</include>

The page opens an email, saves every change in the browser, shows the reason if the editor refuses an email, and exports the email as HTML. `starterEmail` is the email to open when nothing is saved yet. Use one your app already has, or copy the [example email](./document-format#example).

- **Use the full path to `dist/cdn/index.js`.** A shorter URL, such as `https://cdn.jsdelivr.net/npm/@mailquilt/editor`, loads a different build that won't run without a bundler.
- **Pin the version.** MJML, the library that writes the HTML, loads from a file beside the build the first time someone opens Preview or exports, and its name can change between releases. An unpinned URL could ask for a file the latest release no longer has.
- **Save to your server, not only the browser.** This page keeps the email in `localStorage` so it runs on its own. In your app, send the email from `mq-change` to your server, as [Save emails to your server](./save-emails) shows.

## A whole editor page

The CDN build registers `<mail-quilt-shell>` too, the [Shell](./shell): the editor with a header, Export and Import buttons, messages and saving in the browser. Put it on the page instead of `<mail-quilt>` when the editor is a page of its own.

## Content Security Policy

If your page sets a Content Security Policy, `script-src` has to allow the folder the CDN build is in, and the editor needs `'unsafe-inline'` in `style-src`. [Content Security Policy](./api#content-security-policy) has both lines.
